## ネットワーク方針

- 本番は`https://trace-production.async5855.workers.dev/display`をブラウザで開く。参加者は同じoriginの`/log`。旧`trace-log`と本番QRを混ぜない。
- 参加者APIは同一origin `/api/backend`。展示の運営資格・到着proofは同一origin `/api/operator`の限定bridge、描画資格発行とWSSはGo直通。
- 本番展示PCへNode.js・gcloud・旧loopback broker・Edge secret・ローカルネットワークアクセス許可を要求しない。旧リハーサルの8790手順は別構成である。
- `status/close/stop/fallback`等の管理APIは公開bridgeの対象外。必要な別運営入口と担当権限を確認し、secretをブラウザへコピーしない。
- 展示PCへ学内から受信ポートを開放しない。主機は可能なら有線。画像の一斉クラウドupload帯域やGPS連続送信を現行負荷条件にしない。
- 個人operator資格・displayToken・Google ID tokenはブラウザメモリだけ。共有端末の永続領域・URL・スクリーンショットへ残さない。

## 障害時のフォールバック

- 主機停止時は接続・snapshot・leaseを確認して代替機へ移る。切断時にskipされた演出を代替機が勝手に再生せず、既存の明示retry契約で扱う。
- ネットワーク障害は合成経路・抽象映像/承認済み保存映像を使用し、参加者実経路・写真をデモ素材へ転用しない。
- 到着QR発行失敗では偽QR・無認証常時QR・匿名ID手入力を作らない。権限・接続を確認し、観覧を案内する。
- 端末写真はクラウドから復旧できない。撮影/容量/消去エラーとmetadata通信エラーを分けて案内する。

## 予備品・安全

映像/音声/LAN/電源ケーブル・変換器、養生材、必要時の予備回線/電源、合成映像を確認する。OS更新・スリープ・個人通知・スクリーンセーバーを調整し、強い点滅・投射光・排熱・音量・避難経路に配慮する。撮影ルールと端末内保存・本人削除の説明を掲示し、カメラ/GPS両許可を参加条件とする旧案内を使わない。

終了は[終了手順](deployment-operations.md#終了手順)に従い、資格失効・Googleログアウト・借用物返却・原状復帰を個別に記録する。機材電源を切ることと、本人権利/清掃に必要なクラウド資源停止を混同しない。
