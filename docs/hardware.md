# 機材構成

## 推奨割り当て

| 機材 | 役割 |
|---|---|
| Mac mini M4 | メイン描画、プロジェクター出力 |
| ノートPC 1 | 運営ダッシュボード、監視 |
| ノートPC 2 | 受付、到着チェックイン、演出操作 |
| ノートPC 3 | バックアップ描画、ログ監視、開発 |
| Raspberry Pi 4 Model B | 死活監視、NFC、LED・照明・音響制御候補 |
| プロジェクター | メイン3DCG投影 |

GPU性能の高いノートPCがある場合は、その端末をメイン描画に割り当て、Mac miniをバックアップ描画または運営端末に変更する。

本番のGo Backendと正本DBは、Google Cloud東京またはAWS東京の承認済み環境を前提とする。Mac miniやノートPCをサーバーにする構成は、開発または承認済みの緊急構成に限定する。

## 確定が必要な仕様

| 項目 | 確認内容 |
|---|---|
| 描画PC | GPU、メモリ、映像出力、冷却、8時間負荷時の安定性 |
| プロジェクター | 輝度、解像度、投射距離、レンズ、入力、設置方法 |
| 音響 | 音量上限、出力端子、オーディオIF、スピーカー配置 |
| ネットワーク | 有線LAN、学内Wi-Fi、モバイル予備回線、必要帯域 |
| 参加端末 | 対応ブラウザのカメラ・位置同時利用、写真縮小時のメモリ、アップロード速度 |
| 電源 | 回路容量、電源タップ、UPS、接地、予備ACアダプター |
| ケーブル | HDMI/DisplayPort、音声、LAN、電源、変換、予備品 |
| 会場 | スクリーン寸法、遮光、排熱、騒音、養生、避難導線 |

各機材について、型番、数量、所有者、設置場所、代替品、動作確認日を別紙の機材台帳へ記録する。

## ネットワーク方針

- 参加者向けWebアプリはHTTPSで公開する
- 展示PCは外向きWebSocketで接続する
- 通信断時は最後の状態または自律アニメーションで展示を継続する
- Raspberry Piを大人数用アクセスポイントの中心にはしない
- 設営前に学内ファイアウォールとWi-Fi利用条件を確認する
- 参加者向け回線と運営・描画接続の依存関係を確認する
- 主描画機は可能なら有線接続し、Wi-Fiだけを単一障害点にしない
- 20端末相当の写真同時アップロード中も位置送信と描画通信が継続する帯域を確認する

## 障害時のフォールバック

- メイン描画停止: バックアップ端末で簡易展示を起動
- インターネット切断: 保存済み軌跡を使った生成映像へ切り替え
- 到着判定停止: 受付端末から匿名IDを手動選択
- GPS精度低下: QRチェックポイントを利用

## 予備品・安全

- 動作確認済みのバックアップ映像と再生端末
- 予備の映像・音声・LAN・電源ケーブルと変換アダプター
- ケーブルカバー、養生テープ、ラベル、結束用品
- 必要に応じてUPSと予備回線
- 会場承認済みの電源・設置・転倒防止方法
- OS自動更新、スリープ、通知、スクリーンセーバーを本番用設定で確認する
- 写真撮影ルール、原写真の非公開、写真なし参加を説明する会場サイン
