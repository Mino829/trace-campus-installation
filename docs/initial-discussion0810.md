# 意見書　code-yuto

まずは設計書の作成ありがとう
現状の設計書で特段とおかしい点はないと思います。
なのでもう担当分けて開発していいと思います。

設計書があるとはいえ、皆様がその通りに設計できるとも限らないし時間に限りもあるのでアジャイル型で随時うまく変更しながら作成していこう。

APIの要件は最初に決めておいてある程度の処理の流れをUML図とかで書いておこうか。そうすればいいんじゃないかな。

各端末の役割やデータの流れを確認できるように、UML図を別の資料へまとめました。

- [UML図・システムフロー](uml-diagrams.md)

ユースケース図、配置図、コンポーネント図に加えて、通常参加から到着演出まで、追跡停止・データ削除、通信断・再接続のシーケンス図を記載しています。実装中に構成やAPIを変更した場合は、設計書とこの図も随時更新していきます。
