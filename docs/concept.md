# 作品コンセプト

本資料は2026-10-26の決定（Issue #23）に基づき、GPSを一切使わない仕様へ改訂した。撮影時GPS・リアルタイム存在表現・経路の信頼度表現は廃止し、写真の地点は参加者が3Dマップ上で選んだチェックポイント（`checkpointId`）だけを使う。

写真保存先の変更は未実装・未承認の設計目標である。新規写真の画像バイト列は撮影したWeb Appの端末内だけに置き、Backendには写真ID・撮影時刻・`checkpointId`など経路用の最小メタデータだけを保存する。写真のアップロード署名URLや新規クラウド写真保存は使わない。旧方式でクラウド保存済みの写真は前倒し削除せず、本人の照会・削除と各`deleteAfter`の期限削除を維持する。同意文の正本と保護条件は大学承認待ちである。

## 一文で表すと

「写真に残した瞬間と、そのあいだを歩いた時間が、すでに展示だった。」

参加者は写真を撮り、その瞬間の場所を3Dマップ上で自分で選ぶ。作品は、写真の瞬間と、参加者がその瞬間に選んだ場所をつなぐ道として再構成される。正確な位置追跡は目的としない。

## 体験

1. キャンパス入口でQRコードを読み取る
2. 利用目的を確認し、カメラの使用を同意する（位置情報の同意はない。到着QRの読取にカメラを使う）
3. キャンパス内を自由に歩き、残したい瞬間を写真に撮る
4. 写真を撮るたびに、その瞬間の場所を3Dマップ上のチェックポイントから選ぶ（必須）。画像は端末内に保存し、経路用メタデータだけをサーバーに送る。端末保存とサーバー受理は別の状態として分かる
5. 展示ブースの列に並び、自分の番に投影された到着QRを読む
6. サーバーに受理された写真地点を撮影順に最短経路でつなぎ、最後の地点からShibaLab（到着）までの区間も同じ線で10〜20秒の再生として見る
7. 再生後、撮影した端末の同じブラウザに写真が残っていれば写真ストーリーを見返せる
8. 完了状態・サーバーの自動削除予定日時をスマホで確認し、残したい写真は自分で端末のファイル／写真アプリへ保存する

展示で演出中は到着QRを隠し、正常完了後は短い終了画面を挟む。終了画面後に待機があれば次を自動再生し、なければQR画面へ戻る。有効な到着は非表示中も受け付け、通常は順番を待って再生する。30秒経過だけではスキップしない。安全上限50件の満杯時は新しい到着を一時停止し、既存待機を維持する。QRを読んでも必ず直後に再生されるとは限らない。氏名やセッションIDは公開せず、色・記号の照合もしない。機器障害や閉場時の運用は未決。

## 参加しない人の体験

- GPSは端末でもサーバーでも取得しない。位置情報の提供を参加条件にすることはあり得ない
- カメラを許可しない人は参加せず、展示を観覧する。代替参加は用意しない
- 参加しないことによる不利益や、スタッフからの参加圧力を生じさせない

## 表現への変換

- 写真撮影: 光の誕生、波紋、花、色の変化
- 写真の瞬間: 撮影イベントを画像内容から独立した抽象的な光や色として描く。原写真・画像から抽出した特徴はサーバーに送らず公開表示しない
- 写真間のつながり: 参加者が選んだ地点を結ぶ再構成経路を光の道として描く
- 写真地点の名称: スポット名を会話のきっかけとして表示する
- 座標の誤差・不確かさを含めた、GPS由来の信頼度やぼかしの表現は廃止した（2026-10-26決定、#23）

## 展示モード

- 到着時: サーバーに受理済みの写真地点と、その間の再構成経路を追跡再生する。全体10〜20秒、区間の長さに比例配分し、写真地点で少し停止する
- 本人用写真ストーリー: 撮影に使った端末の同じブラウザに残る写真と、受理済みの再構成経路をスマホで時系列に表示する
- リアルタイム存在表現・集合表示はGPS廃止に伴い廃止した。展示は写真メモリー再生＋スポット名表示に縮小する（2026-10-26決定、#23）

## 廃止した要素

次の要素は仕様決定（2026-10-26、Issue #23）により廃止した。詳細は各仕様文書を参照。

- リアルタイム位置の取得・表示（`LivePresenceSession`、`on_site`、geofence、量子化・平滑化）
- ExperienceLink、色・記号による本人照合、`display_alias`
- 撮影時GPS・写真EXIF位置、経路の推定信頼度（`high` / `medium` / `low`）
- 3D Mapへの短期写真ピン、フォトスポット集計（3件以上の閾値表示）
- 到着キューの集合表現への参加表示、待ち時間の表示

## 体験上の原則

- 参加状態、端末内写真とサーバー受理済みメタデータの状態、写真ストーリー、削除操作を参加者自身が確認・操作できるようにする。別端末・別ブラウザへの移行やブラウザデータ削除・容量不足・ストレージの自動整理（eviction）で画像が失われた場合、サーバーから写真は復元できない
- 写真が0枚でも1枚でも、通信が切れた場合でも、参加者を失敗扱いにしない。オフラインでは端末内に写真と再送待ちメタデータを保持し、同じブラウザで再接続時にメタデータだけ送る。容量上限は保存成功の保証ではない
- 色だけに依存せず、形、記号、動きを併用する
- 強い点滅や過大な音を避け、必要な注意と代替導線を会場入口に示す
- 写真原画像は本人の画面に限定し、公開スクリーンでは抽象表現だけを使う
- 撮影枚数や写真の内容を評価・ランキング化しない
- 写真・経路用メタデータの本人削除はそれぞれ端末とサーバーで実行し、片方の失敗を成功と表示しない。サーバーの`deleteAfter`ではメタデータと旧クラウド写真を期限削除するが、端末内写真はWeb Appを開かない間に自動消去できるとは保証せず、本人が別途保存した写真も自動では消えない
