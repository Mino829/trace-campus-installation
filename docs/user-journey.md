# 参加者ジャーニー・画面要件（完成版）

更新日: 2026-11-06

## 基本方針

- 新規参加の入口は`/log`。`/`は旧参加者の状態確認・停止・削除用として残す
- 新しいGPS取得・送信は行わず、位置権限を参加条件にしない
- Backendの同意本文・版・言語を先に表示し、明示同意とMemory作成成功後に参加を開始する。設定取得失敗・受付停止・通信失敗をローカル参加成功にしない
- カメラ機能の有無は開始前に確認し、権限は初回利用時に求める。通知は別の任意操作で許可を求める
- 写真は端末内だけに保存し、写真ごとに選ぶチェックポイントと時刻等のmetadataだけをGoへ送る
- 「作品を見る」と「QRコードを読み取る」を別操作にする。作品閲覧に到着QRや展示再生完了を要求しない
- 「記録を残して参加を終了」と「参加をやめる（写真・参加記録の削除）」を区別する
- 同じブラウザの再読込・別タブでは同じ資格と端末写真を使う。別ブラウザ・別端末への同期はない
- 日本語・英語を切り替えても参加資格・写真を作り直さない。同意は日本語正本と、対応版の参考英訳を区別する
- 作品の会期は2026年10月31日〜11月1日で終了済み。以下は完成コードの導線であり、現在の受付・通知稼働や再展示の案内ではない

## 正常系ジャーニー

| 段階 | 参加者の操作・認識 | システム処理 | 成功の意味 |
|---|---|---|---|
| 1. 発見 | 同じ展示環境の参加ページを開く | `/log`、言語・ブラウザ条件・公開設定を表示 | 作品、任意参加、写真が端末内に残ることが分かる |
| 2. 説明 | 取得する情報、写真の扱い、期限、停止・削除を読む | Backendの同意本文・版・言語を表示 | これから同意する本文を確認できる |
| 3. 同意 | 表示された説明に同意して参加する | Memoryのみ作成し、成功応答から資格・期限・同意記録を保持 | サーバーで作成成功。Liveは作らない |
| 4. 撮影 | 撮る操作でカメラを開き、写真を確認する | 初回利用時のカメラ許可、JPEG変換 | 位置権限なしでプレビューできる |
| 5. 場所選択 | 建物・階・チェックポイントを選び追加する | JPEGと選択地点をIndexedDBへ保存。到着前metadataを非同期送信 | 端末内に写真が残る。展示への反映成功とは別 |
| 6. 任意通知 | 必要なら30分リマインダーを有効にする | 別同意・通知許可後にGoへ購読 | 拒否・非対応でも撮影を続けられる |
| 7. 本人作品 | 写真一覧下の「作品を見る」を押す | ローカル写真・固定Graphの振り返り3D・作品JPEGを表示 | 到着前でも見て保存でき、ホームへ戻って撮影できる |
| 8. 初回到着 | 会場で投影中の有効QRを読む | Memoryの初回到着を登録、FIFO待機へ | 本人状態で到着・再生状態を確認できる。順番や待ち時間は出さない |
| 9. 展示再生 | 会場の光の経路を見る | 単一主描画機で待ち列先頭を再生 | 本人写真を送らず、受理済み地点経路を描画 |
| 10. 再視聴 | 完了後に新しいQRを自分で読む | 同じMemoryの新しい公開再生IDをFIFO末尾へ追加 | 初回到着・写真・期限を作り直さない |
| 11. 持ち帰り・終了 | 作品・写真を保存し、続ける・終了する・削除するを選ぶ | 操作ごとに別処理 | 停止と削除、保存コピーとアプリ内データの違いが分かる |

写真0枚でも到着できるが、写真が端末にない場合は本人作品を生成できない。1枚なら作品とShibaLabへの経路を利用できる。到着後も参加が有効なら写真を撮れるが、新しい写真は本人端末にのみ追加され、展示経路のmetadataへ送られない。

## 画面一覧

### 入口・概要

- 作品の一文説明、写真と場所選択から作品になる流れ
- 写真が端末内のみであること、同じブラウザを使うこと
- 日本語・英語切替
- 既知の旧版・アプリ内ブラウザ・カメラ機能なしでは開始を止め、Safari・Chrome等で開く案内
- 主な案内対象はiOS 16.4以上とAndroid版Chrome 111以上。実装ではFirefox/Safariの既知旧版も判定するが、全環境の試験合格を意味しない
- iPhone/iPadのSafariタブでは、通知にはホーム画面Web Appが必要と案内する。通知なしのタブ参加も可能
- ホーム画面Web Appへ途中で移ると参加をやり直し、元ブラウザの写真は新しい画面へ移らない旨を案内する
- プライベートブラウズでは保存が維持されない場合があるため通常ブラウザを案内する

### 説明・同意

- 正本はBackend公開設定の同意本文・版・言語
- 日本語本文の上に、対応する版がある場合のみ参考英訳を表示。英訳未登録を同等の承認済み英語同意として扱わない
- 写真の端末保存、地点metadata、公開スクリーンに写真を出さないこと、保存期限・削除・問い合わせ先
- 任意参加と、同意しなくても会場鑑賞できること
- 同意して開始、戻る操作。参加後もメニューから同意した本文を再確認できる
- 同意版が変わって参加作成が409となった場合は新本文を取得して表示し、改めて本人操作を求める。押した後に取得した本文へ自動同意しない

### 参加中

旧称「追跡中」の画面は、写真一覧と撮影のホーム画面に置き換える。

- 撮影ボタン、写真一覧、枚数上限
- 写真ごとの保存・削除操作
- 任意の30分リマインダーと利用可否。15分選択は提供しない
- 写真一覧下部の「作品を見る」と「QRコードを読み取る」
- メニューの遊び方、同意事項、記録を残して参加を終了、参加をやめる
- GPS取得中、最終位置更新、精度低下、写真ピン反映の表示は不要。新しいGPS処理そのものがない

現行UIはmetadataごとの送信進行・拒否状態を表示しない。端末写真の追加完了をサーバー・展示への地点登録完了と案内しない。

### 撮影確認

- 写真プレビューと撮り直す操作
- 画像は向きを読み取り、長辺1280px以下・品質0.8のJPEGへ再エンコードし、EXIFを引き継がない
- 建物・階・チェックポイントから場所を選ぶ。位置の自動取得・EXIF位置の補完はしない
- 選択して追加すると端末IndexedDBへ保存。保存中は二重操作を抑え、失敗時は場所選択に戻してエラー
- 他人の顔・名札・個人情報・撮影禁止場所を写さない案内
- 到着前のmetadataだけを非同期送信する。通信断でも保存済み画像は端末に残る

### 本人作品（到着前後共通）

- 「作品を見る」はQR不要。カメラ、到着状態の照会、到着登録、再予約、metadata送信待ちを始めない
- 写真順の振り返り3Dと場所の一覧、写真を一枚にしたJPEG、写真一枚ずつの表示・保存・削除
- 本人端末の経路はローカル写真からShibaLabまでを組み立てる。Goの受理済み展示経路との完全同期ではない
- 生成失敗はエラーを表示。写真0枚では作れない理由と撮影したブラウザで開く案内
- iPhone/iPadは共有シート、その他はダウンロード。非対応なら画像長押しで保存する案内
- 保存しても期限は延びず、保存したコピーはアプリ内削除では消えない
- 期限以降にアプリを開いたとき端末内写真を清掃すること、閉じている間の自動消去は保証しないこと
- ホームに戻って撮影を続けられる。参加終了後は閲覧・削除の導線を残し、QR導線を隠す

### 到着後

- 初回到着は`POST /v1/memory-sessions/{id}/arrival`を使う
- 投影QRは同じoriginの`/log` URLで、短命proofはfragmentに含む。標準カメラでもアプリ内スキャナーでも同じ形式を使う
- 未参加時に読んだproofは参加後に持ち越さない。他originへ資格情報を送らない
- 到着受付後の`queued` / `playing` / `completed` / `skipped`を本人状態から復元する
- 待ち順・予想待ち時間・照合用色や記号は表示しない。「読んだ直後に必ず再生される」と保証しない
- 本人の再生スキップは未再生の待機を対象とする。参加停止・削除は別操作
- 到着による通知停止は参加時の同意方針に従う。通常・既存Memoryは停止、新同意版で継続方針を固定した新規Memoryだけは期限まで継続可能
- 旧Liveの会場内継続や点・エリア・操作時表示の選択は行わない

### 完了・会場内

- 「作品を見る」で本人作品を確認・保存する
- 有効Memoryの`completed`後だけ「もう一度QRコードを読み取る」（英語`Scan the QR code again`）を使える
- 新しいQRを読んだ本人操作だけが`POST .../arrival/replay`へ進み、新しい公開再生IDでFIFO末尾へ入る
- 待機中・再生中の再読取や別タブ競合は既存状態へ戻り、二重予約・割込みをしない
- 初回の到着時刻・終端・Memory期限を更新しない。再視聴で写真・参加・metadataを作り直さない
- スキップ後、本人停止後、期限後は再視聴を申し込まない。作品閲覧は保持期限内で継続できる

## 例外系

| 状況 | 参加者への案内・画面 | 処理上の境界 |
|---|---|---|
| 受付停止 | 参加を受け付けていないと表示 | Memoryを作らず、偽のローカル参加へ進めない |
| 設定取得・参加通信失敗 | 通信・サーバーエラーと再試行 | 成功応答なしに資格・同意を確定しない |
| 同意版変更 | 新しい本文を読み直すよう案内 | 新しい明示同意が必要 |
| 位置権限が拒否状態 | 参加に位置権限は不要 | GPS取得を試みず、許可変更を求めない |
| カメラ拒否 | ブラウザの設定変更・再試行 | 撮影・アプリ内QR読取は成功にしない。鑑賞は可能 |
| 画像変換・端末保存失敗 | エラー、再試行・撮り直し | 写真を追加済みにしない |
| 写真上限 | 一覧確認・削除を案内 | 上限を超えた追加を止める |
| metadata通信断 | 写真は端末内に残る（個別の通信待ちUIはない） | online復帰等で再試行。429は指定時間待つ。展示反映を保証しない |
| Graph版違い | 新規地点登録が拒否される場合がある | 旧IDを現行の座標へ読み替えない |
| 通知拒否・非対応 | 通知なしで参加継続 | 必須権限にしない。iOSはホーム画面要件を案内 |
| 通知遅延・重複 | 厳密な時刻保証はない | 写真体験・到着成功とは分離する |
| 到着QR期限切れ・別環境 | 展示中の正しいQRを読み直す案内 | 到着成功にしない。他originへ本人資格を送らない |
| 到着通信の応答喪失 | 再試行可能な失敗表示 | 同じ画面の再送はendpoint・時刻・キーを固定し、重複登録を防ぐ |
| 外部QRの処理失敗 | 失敗を表示して次の本人操作を待つ | カメラを自動起動しない |
| キュー満杯 | 受付エラーと再試行 | Backendは到着・proof消費等を確定しない。写真・参加は作り直さない |
| 再読込・別タブ | 同じ参加と写真を復元 | localStorage資格とIndexedDB。変更通知・ロックで競合を抑える |
| 別ブラウザ・別端末 | 参加したブラウザで開く案内 | 画像・参加の移行やクラウド復旧はしない |
| 参加停止失敗 | エラーと再試行 | 成功前に終端化した表示にしない |
| 写真削除失敗 | エラーと再試行 | metadata削除が必要な場合は先に確定し、一般の通信失敗でローカル写真を先に消さない |
| 全体削除失敗 | 参加をやめられなかったと表示 | サーバー削除成功前に資格・端末写真を消さない |
| 期限到来・資格が消失 | 参加終了／次回表示で清掃 | `expiresAt`と`deleteAfter`を区別。Backend清掃だけでは端末写真は消えない |
| 描画停止 | 再生状態・失敗の扱いを確認 | 主描画leaseと運営フォールバックで扱う。本人写真を失わせない |

## 自分の演出の識別

会場の案内に従い展示QRを読むことと、本人画面の再生状態で確認する。氏名・セッションID・照合用の色や記号をスクリーンへ表示する方式は使わない。FIFOの前に待機者がいる場合はすぐ再生されないため、本人画面の状態を基準とし、読み取った直後の他者の演出を本人のものと断定しない。

## アクセシビリティ

- 主要ボタンのラベル、状態文、モーダルの閉じる操作、画像の代替文を備える
- 色だけで状態を伝えず、日本語・英語の文言を用意する
- 動きを減らす設定に応じた撮影時演出と、WebGLがない場合の場所一覧を用意する
- 作品生成失敗・保存非対応でも元の端末写真を失わない
- キーボード・読み上げ・200%拡大、実端末・投影での最終受入結果は未確認。コードの配慮を試験合格と記載しない

## 停止と削除の整理

| 操作 | 継続撮影・到着・再視聴 | 既存写真・本人閲覧 | 通知 |
|---|---|---|---|
| 通知だけ解除 | 有効参加なら可能 | 残す | 購読を削除。停止条件に達していなければ任意再購読可 |
| 記録を残して参加を終了 | 不可、再開しない | `deleteAfter`まで閲覧・削除を維持 | 停止 |
| 写真単位削除 | 他の写真・参加は維持 | 選択画像と対応metadata・経路参照を削除 | 参加全体の終了ではない |
| 参加をやめる | 不可 | Memory・資格・端末内写真等を削除 | 停止 |

旧`/`のMemory・Liveは別資格のまま本人状態・停止・個別削除・両資格による全体削除を維持する。新規Live・GPS送信・会場内継続を復活させない。
