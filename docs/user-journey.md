# 参加者ジャーニー・画面要件

本資料は2026-10-26の決定（Issue #23）に基づき、GPS不使用・写真地点自己申告の仕様へ全面改訂した。リアルタイム位置・`LivePresenceSession`・`on_site`・集合表現への参加・色・記号による照合表示の記述は廃止した。Web Pushは30分ごとの撮影リマインダーのみである。

写真保存先の変更は未実装・未承認の設計目標である。新規撮影写真のバイト列はWeb Appの端末内（IndexedDB等）だけに保存し、サーバーには写真ID・撮影時刻・撮影順・`checkpointId`等の経路用最小メタデータだけを送る。新規写真のアップロード署名URL・クラウド保存は行わない。旧Cloud Storage方式で保存済みの写真は前倒し削除せず、本人資格による照会・削除と各`deleteAfter`の期限削除を維持する。同意文正本・保持期間と保護条件は大学承認待ちである。

## 基本方針

- カメラ権限のブラウザダイアログを出す前に、作品側の説明と同意を完了する。位置情報の権限は要求しない
- カメラ権限の説明を権限要求前に示す。カメラの許可が参加の条件である
- 参加中か、完了したか、期限切れかを常に明示する
- 「写真の端末内保存」「経路用メタデータのサーバー受理」「本人が行う写真のファイル／写真アプリへの保存」「保存済みデータの削除」をそれぞれ別の状態・操作として説明する
- セッションIDをスクリーンや運営画面へそのまま表示しない
- カメラを許可しない人は参加せず、展示を観覧できる。代替参加は用意しない
- 対象はiOS 16.4以上とAndroid版Chrome 111以上とする。対象外の版とアプリ内ブラウザでは参加を始めず、Safari・Chromeで開くよう案内する。アプリ内ブラウザの記録はSafari・Chromeと共有されず、途中で移ると参加を続けられないため
- iPhoneではホーム画面に追加したWeb Appから始めるよう案内する。通知はホーム画面のWeb Appにしか届かないため。Safariのタブのままでも参加できる
- 同じ端末・同じブラウザに参加トークンと写真が残っていれば、再読込・別タブ・通知から開き直して同じ参加を続けられる。ブラウザデータの削除・ストレージの自動整理（eviction）・端末紛失・別端末や別ブラウザへの移動では写真を復元できない。同じ人がもう一度参加することは止めない
- 写真を思い出の主役とし、公開スクリーンには原写真を表示しない。サーバー側のメタデータだけでは写真の復元・他端末への移行はできない

## 正常系ジャーニー

| 段階 | 参加者の操作・認識 | システム処理 | 成功条件 |
|---|---|---|---|
| 1. 発見 | 入口の案内とQRを読む | 参加URLを開く | 目的、所要時間、通信・電池、任意参加が分かる |
| 2. 説明 | 写真は端末内のみ、経路用メタデータはサーバーに保存されること、容量・消失リスク、本人による手動保存と削除、位置情報を取得しないことを読む | 承認された同意文を用意する（正本は承認待ち。未承認の保護条件を確定表示しない） | カメラの権限要求前である |
| 3. 同意 | 同意して開始する | 匿名の`MemorySession`を単独で発行する設計目標 | 同意版と記録言語を記録する。LivePresenceSessionは発行しない |
| 4. 権限 | ブラウザのカメラ利用を許可する | カメラを準備する | カメラを許可した場合だけ撮影へ進む |
| 5. 撮影 | 残したい瞬間を撮り、写真ごとに3Dマップで地点（チェックポイント）を選ぶ | 加工済み画像は端末内のみに保存し、写真ID・撮影時刻・撮影順・`checkpointId`等のメタデータだけ送る。座標・ノードID・グラフ版・画像バイト列は送らない | 端末内写真保存の成功とサーバーのメタデータ受理を別々に表示する |
| 6. 到着 | 展示ブースの列に並び、表示中の到着QRをWeb Appで読む | 到着証明を検証し、再生待ちとして登録して撮影通知を停止する | 通知が停止し、再読込しても状態が戻る。待機上限・満杯時は未決 |
| 7. 再生 | 展示ブースで写真メモリーの再生を見る | 演出中はQRを非表示にし、終了後に再表示する。直前にQRを読んだ参加者の有効な到着は再生中も受け付ける。写真地点を撮影順に最短経路でつなぎ、最後の地点からShibaLabまで再生する | 他者のID、生位置、原写真を表示しない。通常の待機時間だけでskipせず、到着順に再生する |
| 8. 完了 | 撮影したブラウザに写真が残ればストーリーを見返し、残したい写真を明示操作で端末のファイル／写真アプリへ保存する。サーバーの自動削除予定日時を確認する | 完了状態と端末内写真の有無・受理済みメタデータを区別して表示する。順位・待ち時間・集合表現への参加は出さない | 参加資格を持つ本人だけがサーバーの記録を閲覧できる。新規写真画像はサーバーから取得しない |

## 画面一覧

### 入口・概要

- 一文コンセプト
- 推奨所要時間
- カメラ利用、写真枚数・ブラウザ容量には保存の保証がないこと、公開スクリーンに原写真を出さないこと
- 位置情報を取得しないこと。写真の地点は参加者が3Dマップで選び、写真は端末内のみ、経路用メタデータはサーバーに保存すること
- 「参加する」と、カメラの許可が参加の条件であること
- 対象外の版では「参加する」の代わりに「この端末では参加できません」を出す
- アプリ内ブラウザでは「参加する」を押せなくし、Safari・Chromeで開くよう案内する
- iPhoneのSafariのタブでは、ホーム画面に追加して始める案内と「通知なしでこのまま参加する」を出す。このまま参加する場合は「プライベートブラウズでは記録が正常に保存されません。通常のタブで開いてください」も出す
- 日本語・英語切替。同意文の正本と言語別版は大学審査後に確定する。既存の `2026-memory-photo-no-gps-draft-1`（jaのみ）は承認済みの正本ではない

### 説明・同意

- 取得する情報、取得しない情報（位置情報・新規写真の画像バイト列はサーバーで取得しない）
- 新規写真は本人のWeb Appの端末内にのみ保存し、公開せず、サーバーは写真ID・撮影時刻・`checkpointId`等だけを経路用に扱うこと
- 写真ごとに3Dマップ上で地点を選ぶ必要があること
- 展示上の抽象化方法と旧クラウド写真の本人照会・削除・期限削除を残すこと
- ブラウザ保存容量の変動・端末喪失・ブラウザ削除／自動整理による写真消失、別端末・ブラウザへ移行できないこと、本人による手動保存、サーバーの削除予定日時と端末内自動消去の限界、停止、削除、問い合わせ先。未承認の具体的な保持・保護条件は確定値として提示しない
- 同意チェックと開始ボタン

### 参加中

- 状態: 写真の端末保存待ち／保存済み／保存失敗と、サーバーのメタデータ送信待ち／受理済み／再送待ち／失敗を別々に表示する。「保存済み」をサーバーに写真アップロード済みの意味に使わない
- 撮影ボタン、撮影枚数、残りの暫定上限と実際のブラウザ保存容量には差がある旨
- 写真ごとの3Dマップ上の地点選択画面。選択が必須であること
- メタデータ再送の進行と、受理前は経路再生に反映されないこと
- 他人の顔、名札、個人情報、撮影禁止場所を写さない案内
- ShibaLab（展示場）への簡易案内。精密ナビゲーションは行わない
- 30分間隔の撮影リマインダー設定。参加の標準として案内し、通知を許可しなくても体験を継続できる
- 撮った写真を本人の明示操作で1枚ずつ端末のファイル／写真アプリへ保存する（Web App内の端末保存とは別）

### 撮影確認

- 撮影写真のプレビュー
- 3Dマップ上の地点選択。チェックポイントを必ず選ぶ（選択しないと保存完了・メタデータ送信に進めない）
- 撮り直す、思い出へ追加する
- 写真は公開スクリーンへ出ず、画像バイト列はサーバーへ送信しないこと
- 端末内写真保存とサーバーのメタデータ送信・受理の進行、失敗、取り消しを区別する

### 到着後

- 「あなたの演出を準備中」
- 再生をスキップして終了
- 撮影通知が停止したことが分かる表示

### 完了

- 完了状態、サーバーの自動削除予定日時と端末内写真が残っているかの別表示。Web Appを開いていない間に端末内写真が自動消去される保証はない
- 同じブラウザに写真が残る場合に限り写真ストーリーを見返す。ストーリーをまとめた画像と写真1枚ずつを本人の明示操作で端末へ保存する。明示保存した端末ファイル／写真アプリ内の写真はWeb Appの期限削除の対象外で、サーバーの`deleteAfter`も延びない
- 写真単位で端末内画像と受理済みメタデータを削除する。旧クラウド写真は既存の本人削除導線を維持する
- セッション全体（端末内画像・送信待ちデータ、サーバーの経路・地点・Push購読・旧クラウド写真等）を削除する。端末側とサーバー側の結果を分けて示す
- 順位・待ち時間・集合表現への参加に関する表示は行わない
- 問い合わせ先

## 例外系

| 状況 | 参加者への案内 | システム処理 |
|---|---|---|
| カメラ権限拒否 | 参加できないことと設定変更方法を案内 | 参加へ進めない。位置権限は関係しない |
| 地点を選択できない | 3Dマップの読み込み・選択肢が復帰した時点で選択を促す | 保存完了・メタデータ送信には進めない。「場所不明の記憶」や写真なし記録の成立、地点の再選択は未決であり採用しない |
| 端末内写真の保存失敗・容量不足 | 保存済みとせず、端末の空き容量・ブラウザ設定の確認と、写真が残っていれば本人による手動保存を案内 | 端末内の写真の有無を確認し、メタデータ受理済みの表示で画像の保存成功を装わない |
| 写真上限到達 | 既存写真の確認・削除を案内 | 新規撮影を停止し既存データを保護する。暫定上限以下でもブラウザ容量不足なら保存できない |
| 通信断・メタデータ送信失敗 | 「写真は端末保存済み／サーバーのメタデータは未受理」、再送・本人による手動保存・削除を案内 | 写真は同じブラウザの端末内に残し、`checkpointId`等のメタデータだけを復旧後に再送する。端末内写真は12枚・合計30MBの暫定上限内でも保存が保証されない |
| 通知が届かない | OS・ブラウザにより遅延することと画面内タイマーを案内 | 写真体験と公開可否には影響させない |
| 通知をオンにできない | 「プライベートブラウズでは記録が正常に保存されません。通常のタブで開いてください」と案内 | 通知なしで参加を続けられる |
| 対象外の端末・アプリ内ブラウザ | 参加できないこと、またはSafari・Chromeで開くことを案内 | 参加を始めない |
| 開き直し | 同じ端末・ブラウザに写真とトークンが残れば再開できる。端末保存済みとサーバー受理済みの状態を確認する | `localStorage`の有効トークンでサーバーの状態を取得し、端末のIndexedDB等から画像を読む。端末にない画像はサーバーのメタデータから復元しない |
| 参加を続けられない・写真が消えた | 「参加を始めた端末の同じブラウザで開いてください。ブラウザのデータが消えた場合や別端末では写真を復元できません。残す写真は早めに手動保存してください」と案内 | 別ブラウザ・端末、iPhoneのSafariとホーム画面Web Appの移動、プライベートブラウズの終了、ストレージ自動整理等で起きる。トークンを失うと本人削除は困難でも、サーバーの記録と旧クラウド写真は各`deleteAfter`で期限削除する |
| 到着QRが無効 | 展示ブースに投影中のQRを読み直すよう案内 | 到着を登録しない |
| 軌跡が短い（写真0枚・1枚） | 簡易表示（スポット名や写真の有無の案内）として再生する | 失敗扱いにせず安全に完了する |
| キュー滞留 | 準備中であることとスキップを表示する | タイムアウト後に自動skip可能 |
| 描画停止 | 再生不能と案内する | フォールバックへ切替しキューを整理する |
| 削除実行・削除失敗 | 写真単位／セッション全体の削除が取り消せないことと、端末内写真とサーバー受理済みデータそれぞれの成功・失敗を表示する。本人が別途保存した写真は自分で削除する | 端末内画像・再送待ちデータとサーバーの受理済みメタデータ・経路・地点・Push購読・旧写真を対象にする。通信断でサーバー削除が失敗すれば同期後に再試行し、`deleteAfter`期限清掃を維持する。端末を開かない間の端末内写真の期限消去は保証しない |
| 経路を確定できない | 「道の記憶が曖昧です」と自然に表現する | 直線を実歩行として保存せず未確定区間とする |

## 自分の演出の識別

参加者は展示ブースの列でQRを読み、氏名や色・記号を公開せずに演出を見る。演出中はQRを隠すが、直前の読取や同時到着があれば待機が発生するため、直後の演出が必ず自分のものと断定しない。色・記号を使わず自分の演出を取り違えない案内方法は、会場での実機・運営確認事項とする（Mino829/TRACE_F#10、#23）。

- 氏名、連番、セッションID、歩いた場所の名称は表示しない
- 参加者が「自分だ」と公に示す操作を必須にしない

## アクセシビリティ

- 主要操作をキーボードと画面読み上げで利用できる
- 200%拡大でも開始・停止・削除が隠れない
- 状態を色だけで伝えない
- 強い点滅を避け、必要な場合は会場入口に警告と代替導線を示す
- 同意文正本は大学審査待ちと明示する。現行草案 `2026-memory-photo-no-gps-draft-1`（jaのみ）を承認済みと扱わず、英語版も審査後に確定する
