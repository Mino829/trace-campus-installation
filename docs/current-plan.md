## 完成版の契約

| 項目 | 現行仕様 | 詳細 |
|---|---|---|
| 参加 | `/log`で公開設定と同意本文を取得し、GoのMemory作成成功後に参加開始。通信失敗や受付停止を端末だけの参加成功にしない | [要件](scope-requirements.md)、[画面](user-journey.md) |
| GPS | 新規取得・送信・Live参加を行わない。旧位置書込みも停止 | [API](api.md)、[プライバシー](privacy.md) |
| 写真 | 画像は端末内のみ。新規サーバー保存はmetadataだけ。地点は固定Graphの選択可能なチェックポイントを本人が選ぶ | [写真仕様](photo-memory.md)、[データ](data-model.md) |
| 経路 | 地点間を固定Graphでつなぐ。実際の歩行記録・現在位置・測量結果ではない | [座標・Graph](coordinate-mapping.md) |
| 本人作品 | 到着前から閲覧・作品画像保存が可能。閲覧だけでは到着・予約・参加終了・通知停止を行わない | [参加者ジャーニー](user-journey.md) |
| 会場再生 | Google認証したthree.js `/display`。運営資格と描画資格を分離し、直接WSSと単一主描画機leaseで制御 | [構成](architecture.md)、[API](api.md) |
| 到着・再視聴 | 短命proofのQRを明示操作。初回到着と完了後の新しい本人再視聴を分け、後者はFIFO末尾へ追加 | [状態遷移](state-machine.md) |
| 通知 | 本番Goの任意30分Push。到着後継続は対応する新しい同意方針の新規Memoryに固定し、既存参加を昇格させない | [プライバシー](privacy.md) |
| 配置 | 参加者`/api/backend`・運営`/api/operator`はCloudflareの同一origin中継。旧loopback方式と混在させない | [インフラ](infrastructure-database-decision.md) |
| 停止・削除 | 停止は参加を終端化するが全削除ではない。既存`expiresAt` / `deleteAfter`を維持し、期限内の本人閲覧・削除を残す | [運用](deployment-operations.md)、[データ](data-model.md) |
| 旧データ | 旧Live・旧GCS写真の本人操作、期限清掃、旧署名URLのfence/outboxを維持。新規受付は復活させない | [API](api.md)、[終了手順](deployment-operations.md#終了手順) |

## 旧計画からの変更

| 旧案 | 完成版での扱い |
|---|---|
| 写真撮影時GPSと常時Liveの二展示 | 新規GPSを廃止。端末写真＋自己申告地点のMemoryを主体にする |
| 新規写真の非公開GCSアップロード | 新規画像は端末内のみ。旧GCSデータの本人閲覧・削除・清掃に限定 |
| 撮影地点のリアルタイム写真ピン・フォトスポット | 廃止。新規の現在位置表示や撮影地点集計を提供する仕様にしない |
| Unity / TouchDesigner / three.jsの比較 | 完成実装はthree.js。旧候補比較を現在の未決事項にしない |
| 通知間隔15分または30分 | 本番Goは30分のみ。旧Workerは別系統として管理 |
| 到着で必ず通知終了 | 既存方針を維持しつつ、新しい同意方針の新規参加に限る到着後継続を実装。全員へ遡及適用しない |
| 到着後にだけ本人ストーリーを表示 | 作品閲覧は到着・展示再生から独立 |
| 一度だけ到着再生 | 初回到着を保ち、完了後の本人新QR操作を別の再視聴予約とする |
| 会期前のMust・日付付き開発計画 | 完成版の採否を記録し、古い納期や未実装案を現在の作業命令として残さない |
