# TRACE 現在計画

- 更新日: 2026-10-26
- 状態: 企画・技術検証中
- 用途: 会議共有用スナップショット

本書の新規写真方針は追加の**未実装・承認待ち設計目標**であり、現行Backendのクラウド写真受付を更新済みと扱わない。新規画像は端末内のみ、Backendには写真ID・`checkpointId`・撮影時刻を送る。従来のクラウド写真は各`deleteAfter`まで本人照会・削除・期限清掃を維持する。同意文の正本・新しい版は関係者相談中（#9）で、既存Mustの変更と大学承認・実装・試験が済むまで実データ受付を開かない。

## 1. 企画概要

TRACEは、キャンパスを歩く参加者が写真に残した瞬間と、その写真の間を移動した時間を作品化するインタラクティブ・インスタレーションである。

参加者は写真を撮ることで自分の思い出を作る。システムは写真撮影地点を記憶の節目として扱い、参加者が3Dマップ上で選んだ写真地点（チェックポイント）をCampusGraphの最短経路でつなぎ、写真と写真の間の道、および最後の写真からShibaLab（到着地）までの道を再構成する。GPSは使わない（2026-10-26決定、Issue #23）。参加はMemorySession単独で成立し、カメラ許可（到着QR読取のため）のみが参加条件である。

会期は2026年10月31日〜11月1日、会場は芝浦工業大学豊洲キャンパス教室棟3F301。開場時間は両日10:00〜18:00。企画・バックエンドはMino829、フロントエンドはcode-yutoとuni-bit、会場描画はcode-yuto、広報・デザイン等はmfunatsu2727-svg、cocoon、tmk-05が担当する。予算上限は5,000円、課金責任者はMino829。描画方式はthree.jsを採用した（2026-10-26、Issue #12）。

## 2. 作品を一文で表すと

「写真に残した瞬間と、そのあいだを歩いた時間が、すでに展示だった。」

## 3. 全体体験

```text
キャンパス入口
  ↓ 入口QR・同意（カメラ許可のみ。位置権限は使わない）
展示A：写真メモリー
    参加者が3Dマップで写真地点（チェックポイント）を選ぶ
    写真の地点を撮影順に最短経路でつなぐ
            ↓
展示場到着・署名・期限付き到着QR（Backend検証）
    撮影通知を停止
    ├─ 写真地点を繋いだ経路の再生（10〜20秒、区間長の比例配分）
    │    0枚は簡易表示、1枚でも写真地点から到着地まで再生
    ├─ 本人用ストーリー・写真の端末保存
    └─ 完了状態と自動削除予定日時の表示
            ↓
終了操作・離脱・期限切れ（サーバーの写真メタデータ・地点・経路は`delete_after`で削除。端末画像は次回起動時に期限検知して消すが、閉じた端末の即時消去は保証できない）
```

## 4. 展示A：写真メモリー

### 目的

参加者がキャンパスで目を留めた瞬間を写真として残し、写真と写真の間にある移動を「記憶の道」として振り返れるようにする。

### 参加フロー

1. 入口QRからWeb Appを開く
2. 写真・写真地点・公開表示・保存期間を確認する
3. 同意後、カメラを許可する（地点選択と到着QR読取のため。位置権限は要求しない）
4. キャンパスを歩きながら、残したい瞬間を撮影する
5. 写真を撮るたびに、撮影時刻と3Dマップで選んだ写真地点（チェックポイント）を記録する
6. 各写真の地点を撮影順にCampusGraph最短経路でつなぐ（最後の写真からShibaLab到着までの区間も含む）
7. 展示ブースに投影された到着QRを読み、展示Aを終了する
8. 到着順に写真の節目と経路を自動再生する（10〜20秒・区間長の比例配分）。正常完了後は終了画面を挟み、次の待機があれば自動再生、なければQR画面へ戻る。演出・終了画面中はQRを非表示にし、通常待機を30秒で自動スキップしない。待機50件で新しい到着だけ一時停止し、既存待機は維持する。障害・閉場時の運用は未決
9. 本人のスマートフォンで写真ストーリーを見返す
10. 写真を端末へ保存するか、写真単位・セッション単位で削除する

### 写真地点・撮影時刻の記録方針

- GPSは一切使用しない。写真地点は参加者が3Dマップで選んだ`checkpointId`のみを記録する
- 端末のpayloadに座標・対応ノードID・グラフ版を含めない。座標とノードの解決はBackendが行う
- カメラの許可は写真撮影と到着QR読取のために要求する。位置権限は要求しない
- 地点未選択・無効な地点では写真メタデータを登録しない。ローカル画像が残る場合は「サーバー未受理」と区別して、地点選択か本人削除を案内する
- 入口QRを開始地点、到着QRを終了地点として使用する
- 画像は同じブラウザのIndexedDBに保存し、写真ID・地点・撮影時刻のメタデータだけ端末に再送待ちとして保持する。通信復旧後に画像を送らずメタデータだけ再送する
- 地点の選び直し（再選択）の可否は未決である（Mino829/TRACE_F#45）

### 写真方針

- 写真を思い出の主役として扱う
- MVPでは1セッション12枚までを暫定上限とする
- 1枚5MB以下、保存後の長辺1920px以下を暫定値とする
- 端末保存前に向き補正、EXIF除去、縮小、再エンコードを行う
- 新規画像は参加端末内だけ、Backendは写真ID・地点・時刻のみを受け付ける。/v2メタデータ・経路はローカル実装済みで、同意/保存方式の大学承認・実配備は別
- 本人の同じブラウザの写真ストーリーだけで新規画像を表示する。ブラウザ領域の消失・容量不足で復元や他端末への移行はできず、本人に手動保存を案内する
- 公開スクリーン、運営画面、ログへ原写真や画像URLを出さない。旧クラウド写真の本人取得・削除と期限清掃は継続する
- 写真は0枚でもよい。カメラを拒否した場合は参加しない

### 公開スクリーンの表現

- 写真撮影時に光、波紋、花、粒子などが生まれる
- 写真の主要色など、元画像を復元できない限定的な特徴を使える
- 写真地点の最短経路を光の線として表示する
- 経路の信頼度表現は廃止した（2026-10-26、Issue #23）
- 写真枚数や撮影頻度をランキング化しない

### 写真ピン・フォトスポット

「写真ピン・フォトスポット集計（FR-031〜033）・個別ピン保護閾値・量子化・セッション固定オフセット・平滑化」は廃止した（2026-10-26、Issue #23）。承認対象は写真地点ベースの展示表現（経路の光の線）へ差し替えた。

### Setlog的な撮影通知

- 通知は参加の標準として案内する。許可しなくても自由撮影と体験完了ができる
- iPhone・iPadではホーム画面へ追加したWeb Appから始めるよう案内する。Safariのタブのままでも、通知なしで参加できる
- 通知権限は説明後の「通知を受け取る」操作から要求する
- 通知間隔は30分ごとの撮影リマインダーとする。精度テスト用の10分通知は廃止した（2026-10-26、Issue #23）。正確な配信時刻を保証しない
- 写真撮影後は次回通知を延期する
- 通知文面に写真、セッションIDを含めない
- 通知を開くと撮影画面へ移動する
- 到着で撮影通知を停止する。停止、期限切れでも送信予定とPush購読を削除する
- Web App表示中はアプリ内タイマーを代替にする
- 運営者は全撮影通知を即時停止できる
- PWA導入率、通知許可率、通知からの撮影率を公開可否の合格条件にしない

## 5. 写真間の経路再構成

### キャンパス経路グラフ

キャンパス内の歩行可能経路を、頂点と辺からなるグラフとして事前に作成する。

頂点の例:

- 交差点
- 建物・展示場の入口
- 階段、エレベーター、スロープ
- 広場や通路の端点
- 入口QR、到着QRの地点

辺が持つ情報:

- 始点・終点
- 実際の通路形状
- 距離
- 屋内・屋外
- 階段・スロープ・エレベーター
- 利用時間、通行止め、立入禁止
- バリアフリー経路の可否

### 経路生成

写真地点の対応ノードをCampusGraph上のDijkstra最短経路（checkpoint-dijkstra-1）で撮影順につなぎ、最後の写真からShibaLabまで同じ線で再生する。0枚は経路なし、1枚でも到着後の区間を持つ（2026-10-29依頼者追加決定）。実際の歩行記録ではなくチェックポイントからの再構成である。

```text
経路の制約 =
  通行可否（通行止め、立入禁止、利用時間）
  + 通路の速度・バリアフリー区分
```

経路は「実際に歩いた軌跡」ではなく、「写真の地点とキャンパス経路から再構成した記憶の道」と説明する。複数の経路候補が同距離で並んでも、いちばん最短の候補を一つ採用する。不確かな区間を実際の歩行として断定しない。

### 経路の廃止事項

- 信頼度（`high`/`medium`/`low`）とaccuracy/uncertaintyの表現は廃止した（2026-10-26、Issue #23）
- GPS精度へのペナルティ評価はGPS不使用により意味を持たなくなり廃止した

## 6. 展示B（入口から終了までのリアルタイム存在表現）

リアルタイム位置表現(`LivePresenceSession`)は廃止した（2026-10-26、Issue #23）。展示画面に描くのは、参加者が選んだ写真地点を最短経路でつないだ事後の再生だけである。`on_site`概念は完全に削除する。

旧LivePresenceSessionは新規発行しない。既存セッションは本人資格での状態照会・停止・削除と、各`delete_after`までの期限清掃のみを残す。旧GPSデータは`deleteAfter`まで保持し、前倒し削除しない(TRACE_B#30)。位置送信・on-siteエンドポイント・旧描画位置イベントの読み取り契約はTRACE_B#30でのみ許容し、新規実装では使用しない。

## 7. セッションとデータ

参加者の新規セッションは`MemorySession`単独である。旧`LivePresenceSession`は廃止済みで、§6の期限清掃・本人照会契約のみが残る。

### MemorySession

- 写真メタデータ（写真ID・地点・撮影時刻・撮影順。画像は保存しない）
- 写真地点（チェックポイント）のBackend側座標・ノード解決結果
- 入口・到着ノード
- 写真地点をつないだ再構成経路（CampusGraph最短経路）
- 本人用画像ストーリーは同じブラウザ内で合成し、サーバーから写真画像を復元できない
- 同意版は新方式用に関係者相談・審査後に決定。旧`2026-memory-photo-no-gps-draft-1`は再利用しない。TTL 6h、`delete_after`=失効後24hは開発側既定

`delete_after`が到来した時点で、サーバーの写真メタデータ・チェックポイント地点・経路・削除冪等性記録と旧クラウド写真を期限清掃する。端末画像はWeb Appを次に開いて期限を検知した時に削除できるが、閉じた端末や本人が写真アプリへ手動保存した複製を遠隔消去できない。APIセキュリティログ30日、DBバックアップ最大7日は提案値であり、大学承認待ちである。

### 廃止した契約（2026-10-26、Issue #23）

`LivePresenceSession`の新規発行、`ExperienceLink`、色・記号・`display_alias`、スマホ↔展示の照合表示、二資格情報による両DELETE、写真の緯度経度列の更新書き込みは廃止した。

## 8. プライバシー・安全

- 写真と写真地点データは完全な匿名情報とは扱わない
- 他人の顔、名札、個人情報、授業資料、撮影禁止場所を写さないよう案内する
- 新規写真の画像は本人の同じブラウザ内に限定し、旧クラウド写真も本人資格以外へ公開しない
- 新規画像と端末の派生物・キャッシュ、サーバーメタデータ・経路、旧写真object・縮小画像・派生物をそれぞれの削除対象に含める
- 生の位置情報、写真、参加トークン、画像URLを通常ログへ出さない
- 写真・写真地点データを研究、広報、SNS、学習データへ自動転用しない
- 参加者は写真単位・セッション単位で削除できる。削除はMemorySessionの本人トークン単独で成立する
- MemorySessionはTTL 6h、`delete_after`=失効後24hとする（開発側既定）。サーバーのメタデータ・地点・経路・削除冪等性記録と旧写真は同一期間で消す。閉じた端末の画像即時削除は保証しない
- APIセキュリティログ30日、DBバックアップ最大7日は提案値であり、大学承認待ちで確定しない

## 10. MVP範囲

### 必須

- 写真撮影（3Dマップでの地点選択含む）、端末画像保存、写真メタデータのみ送信（Must変更の承認待ち）
- EXIF除去、縮小、端末内保存。旧Cloud Storage写真の本人取得・削除・期限清掃
- CampusGraph作成とチェックポイント↔Graphノードの対応管理
- 写真地点を撮影順につなぐ最短経路再構成（ShibaLab到着区間を含む）
- 10〜20秒・比例配分・写真地点で少し停止する経路再生
- 本人用写真ストーリー
- 写真単位・セッション単位の削除
- MemorySession（TTL 6h・`delete_after`失効後24h）と一括期限削除
- CampusGraph・3D Mapの版同期とロールバック（版不一致イベントは破棄）
- 入口QR、署名・期限付き到着QR、到着検証と送信通知の停止
- 30分ごとの撮影リマインダー（通知なし参加可）
- 原写真を表示しない公開スクリーン
- 通信障害時の写真再送・代替体験

### MVP対象外

- 写真の公開投稿、友人共有
- 自動Vlog動画生成
- 写真の人物・文字・物体分析
- 参加者の個人アカウント、SNSログイン、ランキング。運営者の個人Google本人確認は別で採用する
- リアルタイム位置表現・GPS（Issue #23で廃止）
- 屋内・屋外の位置測位機能

## 11. 暫定受け入れ条件

- 対応端末で端末内写真保存成功率99%以上（提案値・実測待ち）
- 保存した端末画像のEXIF残存0件
- 新規写真の画像バイト列の通信送信0件、公開スクリーン・描画イベントへの原写真・画像URL・生座標・生GPS送信0件
- 参加者端末のpayloadに座標・ノードID・グラフ版を含めない
- CampusGraph・3D Mapの版不一致イベントを描画しない（破棄して直前互換版へ戻す）
- 通行不能・立入禁止・利用時間外のCampusEdgeを経路に含めない
- 写真撮影から端末保存・サーバーメタデータ登録までp95で10秒以内（再送時を除く、提案値）
- 写真0枚は経路なしで完了し、1枚でも写真地点からShibaLabまでの区間を再生できること
- 経路再生が全媒体10〜20秒に収まり、区間長の比例配分で写真地点で停止すること
- 到着で送信通知が停止すること
- サーバーの写真メタデータ・地点・経路・削除冪等性記録と旧クラウド写真を各`delete_after`で削除する試験に合格する。端末内画像は次回起動時の期限検知で消すが閉じた端末の即時削除は保証しない
- 本番構成で8時間連続稼働
- 障害時に1分以内で合成・位置なし展示へ切り替え可能

## 12. 実現可能性・成立条件

中心体験である「写真撮影 → 3Dマップで地点選択 → 最短経路 → 到着後の追体験」は既存技術で実現可能性が高い。難しさは個別機能より、実機差、地点選択UIの完成度、大学承認、当日運用の統合にある。

| 領域 | 実現可能性 | MVP判断 |
|---|---|---|
| 写真・地点選択・非公開保存 | 高 | 必須 |
| 最短候補経路 | 高 | 必須。実歩行の完全再現とは説明しない |
| 到着QR検証と再生配信 | 高 | 必須 |
| PWA・Web Push通知 | 中〜高 | Should。通知なし導線を主導線に残す |
| 3Dマップ地点選択UI | 中 | チェックポイント粒度・再選択の未決を含む |
| 50人規模運用 | 中〜高 | 負荷・回線・8時間試験の合格を条件にする |

### 経路再構成の限界

写真2地点だけでは複数経路のうち実際に歩いた道を一意に決められない。作品では「実測軌跡」ではなく「記憶の道」と呼ぶ。最短経路を一つ採用し、実歩行の再現は主張しない。行動の追体験は事実の完全再現ではなく、写真の節目をつなぐ表現として成立させる。

### 制作体制と縮小順序

- Web・Backend、3D・映像、現地検証・運用・個人情報確認の責任を分ける
- 一人または短期間の場合は、地点選択UIの粒度、通知、3D装飾の順に縮小する
- 3Dモデル完成を待たず、主要導線の簡易モデルで経路と再生を先に通す
- 大学相談を実装完了後へ回さず、技術検証と並行する

### 2週間の技術成立性ゲート

1. iPhone・Androidで写真を加工して端末内に保存し、写真ID・地点・撮影時刻のメタデータだけを送る。旧写真の本人照会・削除も維持する
2. チェックポイント地点の選択と簡易3D Mapでの経路表示を通す
3. 写真2〜5枚から最短経路を生成する
4. iOSホーム画面Web AppとAndroidで通知の許可、受信、停止を試す
5. 到着QRの検証と簡易再生（写真0枚・1枚を含む）を通す
6. 通信断中に端末画像と経路用メタデータを保持し、復旧後に画像を送らずメタデータだけ冪等再送できることを確認する

未達機能は、簡易マップ選択、アプリ内タイマー、合成データへ段階的に縮小する。
