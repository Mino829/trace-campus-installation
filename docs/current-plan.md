# TRACE 現在計画

- 更新日: 2026-08-11
- 状態: 企画・技術検証中
- 用途: 会議共有用スナップショット

## 1. 企画概要

TRACEは、キャンパスを歩く参加者が写真に残した瞬間と、その写真の間を移動した時間を作品化するインタラクティブ・インスタレーションである。

参加者は写真を撮ることで自分の思い出を作る。システムは写真撮影地点を記憶の節目として扱い、撮影時のGPSとキャンパス内の歩行可能経路から、写真と写真の間の道を再構成する。

写真メモリーと並行して、希望する参加者は入口から展示終了までリアルタイム位置表現へ参加できる。展示場では、到着前にキャンパスを移動している参加者と、到着後に会場内を動く参加者の両方を表現する。写真メモリーとリアルタイム位置は、同じ参加体験の中で動くが、目的、同意、セッション、保存方針を分離する。

## 2. 作品を一文で表すと

「写真に残した瞬間と、そのあいだを歩いた時間が、すでに展示だった。」

## 3. 全体体験

```text
キャンパス入口
  ↓ 入口QR・同意
  ├─ 展示A：写真メモリー
  │    写真撮影時GPSを保存
  │    写真間の道を再構成
  │
  └─ 展示B：リアルタイム存在表現
       送信できる時だけ最新GPSを送信
       展示場から到着前の参加者も見える
            ↓
展示場到着・到着QR
  ├─ 写真メモリーの軌跡演出・本人用ストーリー
  └─ 展示Bを会場内フェーズとして継続、または本人が停止
            ↓
終了操作・離脱・期限切れ
```

## 4. 展示A：写真メモリー

### 目的

参加者がキャンパスで目を留めた瞬間を写真として残し、写真と写真の間にある移動を「記憶の道」として振り返れるようにする。

### 参加フロー

1. 入口QRからWeb Appを開く
2. 写真と位置情報の目的、公開範囲、保存期間を確認する
3. 同意後、カメラと位置情報を許可する
4. キャンパスを歩きながら、残したい瞬間を撮影する
5. 写真を撮るたびに撮影時刻、撮影時GPS、精度を記録する
6. 前回写真と現在写真の間の経路をキャンパス経路グラフから再構成する
7. 展示場入口の到着QRを読み、展示Aを終了する
8. 写真の節目と再構成経路を10〜20秒で再生する
9. 本人のスマートフォンで写真ストーリーを見返す
10. 写真を端末へ保存するか、写真単位・セッション単位で削除する

### 写真メモリー用GPS方針

- 写真メモリーの経路生成には、常時GPS履歴を保存しない
- 写真撮影時に`getCurrentPosition`を一度実行する
- 撮影位置の取得待ちは暫定10秒とする
- GPSが取得できなくても写真は残す
- 入口QRを開始地点、到着QRを終了地点として使用する
- 写真撮影時GPSは写真と一緒に端末へ一時保存し、通信復旧後に送信できる
- 展示Bで送信した通常GPS点を写真メモリーの履歴として保存・再利用しない

### 写真方針

- 写真を思い出の主役として扱う
- MVPでは1セッション12枚までを暫定上限とする
- 1枚5MB以下、保存後の長辺1920px以下を暫定値とする
- 送信前に向き補正、EXIF除去、縮小、再エンコードを行う
- 写真は非公開オブジェクトストレージへ保存する
- 本人の写真ストーリーだけで原写真を表示する
- 公開スクリーン、運営画面、ログへ原写真や画像URLを出さない
- 写真0枚やカメラ拒否でも、写真なしの抽象表現として参加できる

### 公開スクリーンの表現

- 写真撮影時に光、波紋、花、粒子などが生まれる
- 写真の主要色など、元画像を復元できない限定的な特徴を使える
- 写真間の再構成経路を光の線として表示する
- 経路の信頼度を線の明瞭さ、ぼかし、粒子の広がりへ反映する
- 写真枚数や撮影頻度をランキング化しない

### リアルタイム写真ピンとフォトスポット

- PhotoMomentの保存・検証完了後、撮影時GPSを共通ローカル座標へ変換して3D Mapへピンを配信する
- ピンへ写真、画像URL、正確なGPS、セッションIDを含めない
- 座標は5〜10m単位へ量子化する
- 個別ピンは撮影瞬間の短い演出を基本とし、継続表示する場合も15〜30分で自動消去する
- 少人数時は個別ピンを遅延、追加量子化、短時間化、非表示のいずれかへ切り替える
- CampusNode、CampusEdgeまたは量子化グリッド単位で撮影地点を集計する
- 同一集計単位で3件以上の場合だけフォトスポットとして表示する
- 写真削除時は個別ピンを削除し、保持中の集計を減算する
- 運営者は個別ピンとフォトスポットを別々に一括停止できる

### Setlog的な撮影通知

- 通知は任意で、通知なしでも自由撮影と体験完了ができる
- iPhone・iPadではホーム画面へ追加した対応Web Appを対象とする
- 通知権限は説明後の「通知を受け取る」操作から要求する
- 通知間隔は15分・30分を初期候補とし、正確な配信時刻を保証しない
- 写真撮影後は次回通知を延期する
- 通知文面に位置、写真、セッションIDを含めない
- 通知を開くと撮影画面へ移動する
- 到着、停止、期限切れで送信予定とPush購読を削除する
- Web App表示中はアプリ内タイマーを代替にする
- 運営者は全撮影通知を即時停止できる
- PWA導入率、通知許可率、通知からの撮影率を公開可否の合格条件にしない

## 5. 写真間の経路再構成

### キャンパス経路グラフ

キャンパス内の歩行可能経路を、頂点と辺からなるグラフとして事前に作成する。

頂点の例:

- 交差点
- 建物・展示場の入口
- 階段、エレベーター、スロープ
- 広場や通路の端点
- 入口QR、到着QRの地点

辺が持つ情報:

- 始点・終点
- 実際の通路形状
- 距離
- 屋内・屋外
- 階段・スロープ・エレベーター
- 利用時間、通行止め、立入禁止
- バリアフリー経路の可否

### 経路生成

写真`n-1`と写真`n`のGPSを、それぞれ最寄りの頂点ではなく、原則として最寄りの通行可能な辺上へ配置する。その間をA*またはDijkstraで接続する。

リアルタイム位置は一時表示だけに使い、写真メモリーの経路履歴として保存しない。そのため、基本は写真地点間の最短経路を「推定経路」として採用する。ただし、撮影時の精度、前後の進行方向、通行制約を評価へ加える。

```text
routeScore =
  経路距離
  + GPS精度へのペナルティ
  + 通行不能・時間外経路へのペナルティ
  + 不自然な折り返しへのペナルティ
```

### 信頼度

- `high`: 両端の精度が良く、経路候補がほぼ一つ
- `medium`: 複数経路がある、またはGPS精度がやや悪い
- `low`: GPSを取得できない、グラフ外、経路を決められない

経路は「実際に歩いた軌跡」ではなく、「写真とキャンパス経路から再構成した記憶の道」と説明する。不確かな区間を実際の歩行として断定しない。

## 6. 展示B：入口から終了までのリアルタイム存在表現

### 目的

希望する参加者の最新位置を、入口から展示終了まで光や生命体として表現する。展示場では、これから展示場へ向かっている参加者と、すでに到着して会場内にいる参加者の両方を見られる。

リアルタイム位置は正確な追跡記録ではなく、その時点で通信・測位できている参加者の「現在の存在」をベストエフォートで示す。

### 表示フェーズ

| フェーズ | 期間 | 展示表現 |
|---|---|---|
| `approaching` | 入口参加から到着QRまで | キャンパス内を展示場へ向かう光 |
| `arrived` | 到着QR直後 | 写真メモリーの経路再生へ切り替わる瞬間 |
| `on_site` | 到着演出後から終了まで | 会場内・指定範囲内のリアルタイム反応 |

GPSや通信が途切れた参加者は、最後の位置を残し続けず、30〜60秒で自然に展示から消える。復旧時は新しい現在位置から再び現れる。

### 同意とセッション

- 入口の参加画面で、写真メモリーとは分けてリアルタイム位置の目的、範囲、表示、保持時間を説明する
- 明示的に参加した人だけ`LivePresenceSession`を発行し、入口から`approaching`を開始する
- リアルタイム位置へ同意しなくても写真メモリーへ参加できる
- 到着QRでは新規に自動追跡を開始せず、現在のリアルタイム参加を会場内フェーズへ継続するか停止するかを表示する
- 到着後に利用目的や範囲が変わる場合は、`on_site`開始前に追加同意を取得する
- 展示Aの`MemorySession`と認証、状態、保存データを分離する
- 色・記号を引き継ぐ場合も、短時間の一回限りの引き継ぎ情報を使う

### GPS方針

- 入口で同意した後、展示Bの画面を開いている間だけ`watchPosition`を使用する
- 送信間隔は暫定3〜5秒とする
- 指定したgeofence内の位置だけ受け付ける
- 表示前に5〜10m単位の量子化、固定オフセット、平滑化を適用する
- 生GPS点や移動軌跡を原則として永続保存しない
- サーバーは最新位置だけを一時保持する
- 最新位置は30〜60秒のTTLで自動消去する
- 通信できない通常GPS点を端末へ保存・後送しない。送信できる時点の最新位置だけを送る
- 写真撮影時GPSだけはMemorySessionのアンカーとして写真と一緒に再送できる
- 停止操作、ページ終了、一定時間無更新、セッション期限切れで終了する
- バックグラウンド動作を前提にしない

### 屋内精度への対応

`approaching`ではキャンパス屋外GPS、`on_site`では会場内GPSを使う。会場内で十分な精度を得られない場合は正確な座標として扱わず、次のいずれかを採用する。

- 展示エリア単位の存在表現
- GPS精度を光の広がりへ変換
- QRチェックポイントや物理操作との併用
- GPSが成立しなければ位置なしのインタラクションへ切り替える

MVPでは会場内の正確な点表示より、展示エリア単位の存在表現を既定フォールバックとする。点表示、エリア表示、QR・物理操作の順に切り替え条件を現地試験で決める。

## 7. セッションとデータ

### MemorySession

- 写真
- 写真撮影時GPS、精度、時刻
- 入口・到着ノード
- 写真間の再構成経路
- 経路信頼度
- 本人用写真ストーリー

### LivePresenceSession

- 展示B用の同意版・同意時刻
- `approaching`、`arrived`、`on_site`の表示フェーズ
- 一時的な表示用ID、色、記号
- 最新の量子化済み表示座標
- 最終更新時刻
- TTLと終了時刻

LivePresenceSessionへ写真、生GPS履歴、MemorySessionの再構成経路を複製しない。両展示で同じ色・記号を使う場合も、セッション終了後に長期的な紐付けを残さない。

### セッション間の引き継ぎ契約

- `MemorySession`と`LivePresenceSession`は別ID・別同意版・別状態・別削除期限を持つ
- 参加端末は各セッション用の別トークンを保持する。片方のトークンで他方の写真・位置を操作できない
- 両方へ参加する場合だけ、短時間の`ExperienceLink`で同じ端末上の引き継ぎを行う
- `ExperienceLink`は色・記号と到着処理の連携だけに使い、写真、生GPS、経路を複製しない
- 到着QRはMemorySessionへ到着イベントを作り、LivePresenceSessionを`arrived`へ変更する
- `on_site`を希望する場合だけ、必要な追加同意後にLivePresenceSessionを継続する
- 「すべて削除」は有効な両トークンを使って両セッションを削除し、一方だけの削除も選べる
- `ExperienceLink`は到着、片方の削除、期限切れから24時間以内の最短時点で削除する

## 8. プライバシー・安全

- 写真と位置データは完全な匿名情報とは扱わない
- 他人の顔、名札、個人情報、授業資料、撮影禁止場所を写さないよう案内する
- 写真原画像は本人以外へ公開しない
- 写真、縮小画像、派生色、端末キャッシュを削除対象に含める
- 生位置、写真、参加トークン、画像URLを通常ログへ出さない
- 写真・位置データを研究、広報、SNS、学習データへ自動転用しない
- 参加者は写真単位・セッション単位で削除できる
- 写真とMemorySessionの暫定保持は到着・停止後24時間以内とする
- 展示Bの最新位置は到着前後を問わず30〜60秒以内に自動消去し、軌跡として残さない

## 10. MVP範囲

### 必須

- 写真撮影、撮影時GPS、写真送信
- EXIF除去、縮小、非公開保存
- CampusGraph作成
- 写真間の経路再構成
- 信頼度つきの軌跡演出
- 本人用写真ストーリー
- 写真単位・セッション単位の削除
- 写真撮影地点の量子化ピン、15〜30分TTL、3件以上のフォトスポット
- 少人数時の個別ピン保護モードと、削除時の集計減算
- MemorySessionとLivePresenceSessionの別ID・別トークン・短期ExperienceLink
- 座標変換・CampusGraph・3D Mapの版同期とロールバック
- 入口QR、到着QR
- 展示Bの入口同意、到着前後のリアルタイム位置、一時保持、フェーズ切替、停止
- 原写真を表示しない公開スクリーン
- GPS・写真・通信障害時の代替体験

### MVP対象外

- 写真の公開投稿、友人共有
- 自動Vlog動画生成
- 写真の人物・文字・物体分析
- 個人アカウント、SNSログイン、ランキング
- 正確な屋内測位
- LivePresenceSessionの位置履歴保存

## 11. 暫定受け入れ条件

- 対応端末で写真保存成功率99%以上
- 保存画像のEXIF残存0件
- 公開スクリーンへの写真原画像・画像URL送信0件
- 個別写真ピンへの写真・画像URL・生GPS・正確な時刻・セッションID送信0件
- 個別写真ピンは設定した15〜30分以内に消え、フォトスポットは3件未満で非表示になる
- 座標変換・CampusGraph・3D Mapの版不一致イベントを描画しない
- 通行不能・立入禁止・利用時間外のCampusEdgeを通常経路として採用しない
- 実際と異なる経路または複数候補区間を`high`信頼度にしない
- 実経路との辺一致率は改善指標として測るが、一律90%を公開条件にしない
- 写真撮影から保存完了までp95で10秒以内
- 展示Bの有効位置受信から表示までp95で2秒以内
- 通信停止・展示B終了後60秒以内に最新位置を消去
- 写真、位置、経路、派生データの削除試験に合格
- 本番構成で8時間連続稼働
- 障害時に1分以内で合成・位置なし展示へ切り替え可能

## 12. 実現可能性・成立条件

中心体験である「写真撮影 → 撮影時GPS → 3D写真ピン → 推定経路 → 到着後の追体験」は既存技術で実現可能性が高い。難しさは個別機能より、実機差、屋内GPS、3D座標調整、大学承認、当日運用の統合にある。

| 領域 | 実現可能性 | MVP判断 |
|---|---|---|
| 写真・撮影時GPS・非公開保存 | 高 | 必須 |
| 3D写真ピン・フォトスポット | 高 | 必須。少人数時制御を含む |
| 最短候補経路 | 高 | 必須。実歩行の完全再現とは説明しない |
| PWA・Web Push通知 | 中〜高 | Should。通知なし導線を主導線に残す |
| 到着前リアルタイム位置 | 中 | 画面表示中・送信可能時だけ |
| 会場内の正確な点表示 | 低〜中 | エリア表示を既定フォールバックにする |
| 50人規模運用 | 中〜高 | 負荷・回線・8時間試験の合格を条件にする |

### 経路再構成の限界

写真2地点だけでは複数経路のうち実際に歩いた道を一意に決められない。作品では「実測軌跡」ではなく「推定経路」「記憶の道」と呼び、候補差が小さい場合は信頼度を下げる。行動の追体験は事実の完全再現ではなく、写真の節目をつなぐ表現として成立させる。

### 制作体制と縮小順序

- Web・Backend、3D・映像、現地検証・運用・個人情報確認の責任を分ける
- 一人または短期間の場合は、正確な会場内点表示、通知、3D装飾の順に縮小する
- UnityとTouchDesignerを長期間並行開発せず、技術検証後に一方へ決める
- 3Dモデル完成を待たず、主要導線の簡易モデルで写真ピンと経路を先に通す
- 大学相談を実装完了後へ回さず、技術検証と並行する

### 2週間の技術成立性ゲート

1. iPhone・Androidで写真、撮影時GPS、EXIF除去、送信を通す
2. 主要基準点を共通座標へ変換し、簡易3D Mapへ写真ピンを表示する
3. 写真2〜5枚から最短候補経路と信頼度を生成する
4. iOSホーム画面Web AppとAndroidで通知の許可、受信、停止を試す
5. 屋外と会場内のGPSを測り、点表示・エリア表示・位置なし反応を決める
6. 通信断中の通常GPSを後送せず、30〜60秒で表示が消えることを確認する

未達機能は、アプリ内タイマー、エリア表示、QR・物理操作、簡易3D Map、合成データへ段階的に縮小する。

- 到着後の用途に追加同意が必要なほどの変更があるか
- GPS不成立時に使うQR・物理インタラクション

### 技術・運用

- UnityまたはTouchDesigner
- 本番サーバー、DB、オブジェクトストレージの提供者
- CampusGraphの作成・更新担当者
- 対応OS・ブラウザ
- 写真・位置データの正式な保存期間
- 大学の施設、ネットワーク、個人情報、倫理、広報承認
- 未成年者の参加条件
- 予算、調達、当日担当者

## 14. 次に行う検証

1. iOS・Androidで写真撮影時のGPS取得を試す
2. 写真の縮小、EXIF除去、送信時間、通信量を測る
3. 主要導線のCampusGraphを小さく作る
4. 写真2〜5枚から経路を再構成し、実際の道と比較する
5. 写真0枚、1枚、複数枚の体験を比較する
6. 入口から展示場まで、到着後の会場内の両方で展示BのGPS精度を測る
7. 通信断時に過去点を後送せず、30〜60秒で表示が消えることを確認する
8. 会場内GPSが成立しない場合のエリア判定・QR代替を試す
9. 写真メモリーと到着前後のリアルタイム展示を一台のスマホで通す
10. 写真ピンの量子化、TTL、3件フォトスポット、削除減算を通す
11. 座標変換・CampusGraph・3D Mapの版不一致拒否とロールバックを通す
