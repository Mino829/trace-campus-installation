# 試験計画・公開判定基準

## 目的

作品表現だけでなく、参加開始、写真撮影、位置取得、経路再構成、到着、停止、削除、障害復旧を本番条件で検証し、写真とリアルタイム位置を使って公開できるか判断する。

## 試験環境

- 開発環境: 合成座標のみ。実データを持ち込まない
- ステージング: 本番と同じ認証・DB構成。短時間の同意済み実地試験のみ
- 本番: 承認済みドメイン、機材、ネットワーク、設定を使用
- 試験データ: 名前や実在人物と紐付かない合成セッションを原則とする

## 端末・条件マトリクス

公開前に実機とバージョンを記入する。

| 分類 | 必須条件 |
|---|---|
| iPhone | サポート対象の最古・最新iOS、Safari |
| Android | 主要2メーカー以上、対象の最古・最新Android、Chrome |

| 権限 | 初回許可、拒否、過去に拒否、OS設定で無効 |
| カメラ | 前後カメラ、縦横撮影、高解像度、カメラ拒否、撮り直し |
| 省電力 | 通常、低電力モード、低残量 |
| ブラウザ条件 | 通常、プライベートブラウズ、Cookie制限 |
| アクセシビリティ | 200%拡大、画面読み上げ、キーボード操作 |

## 位置・表現試験

- 正門、主要導線、建物沿い、屋内、展示場入口を各3回以上歩く
- 既知の基準点に対する誤差分布、欠測時間、ジャンプ数を記録する
- 5秒、10秒、15秒間隔で精度、通信量、電池消費を比較する
- 画面状態別に、有効点取得率と最大更新停止時間を記録する
- 生軌跡、平滑化後、量子化後を開発用の限定環境で比較し、公開出力には生座標を残さない
- 誤差が大きい場合にも、消失・瞬間移動が表現として不自然でないか表現責任者が確認する
- 実際に通った既知経路と再構成結果を比較し、辺単位の一致率と誤選択を記録する
- 同距離の複数経路、写真アンカー欠損、建物入口、階段、通行止めを試す
- 写真地点が頂点へ不自然に飛ばず、適切な辺上へ配置されることを確認する

暫定合格値:

- 主要屋外導線で有効点取得率95%以上
- 受信した有効点の95%以上が、受信後2秒以内に描画へ反映
- 追跡不能状態を30秒以内に参加画面へ表示
- 画面ロックで要件を満たせない場合、画面を表示したままにする案内か代替体験を必須とする
- 通行不能・立入禁止の辺を採用しない。候補を一意に決められない区間は`low`または未確定にする
- 誤った経路を`high`信頼度と判定しない
- 実経路との辺一致率は改善指標として記録するが、一律の公開条件にはしない

## 写真試験

- iOS・Androidで縦、横、前後カメラ、高解像度画像を撮影する
- JPEG、WebP、非対応形式、拡張子偽装、破損画像、5MB超、1920px超を試す
- 保存後画像にEXIF、GPS、端末情報、元画像サムネイルがないことを確認する
- 12枚連続撮影、30MB送信待ち、回線切断・復旧、重複completeを試す
- 撮影時GPS取得不能、写真0枚、1枚、12枚でストーリーを生成する
- 写真単位削除後に前後RouteSegmentが再生成または未確定になることを確認する
- セッション削除と期限削除でDB、object、縮小画像、派生色、端末キャッシュを確認する
- 写真保存前後の通信量、処理時間、端末メモリ、電池消費を記録する
- 1件・2件ではフォトスポットが出ず、3件で出て、削除またはTTL後に2件へ戻ると消えることを確認する
- 個別ピンが15〜30分以内に消え、少人数モードで遅延・追加量子化・短縮・非表示を切り替えられることを確認する

暫定合格値:

- 対応端末・通常回線で写真保存成功率99%以上
- 写真撮影から保存完了までp95 10秒以内。再送時を除く
- EXIF残存0件、公開画像URL0件、描画への原写真送信0件
- 削除期限超過写真0件

## 負荷・耐久試験

- 合成クライアント60セッションで、5秒間隔の位置送信を30分継続する
- 50追跡中に3人、5人、10人の同時到着を試す
- 20端末相当で写真アップロードを同時開始し、位置送信と描画が継続することを確認する
- 60セッションが各12枚の写真メタデータを持つ容量試験を行う。実画像は合成テスト画像を使う
- 8時間の描画・Backend・DB連続運転を行う
- WebSocket切断・再接続を繰り返し、イベント重複と欠落を確認する
- DB容量80%相当、ログ出力先逼迫、遅い回線を試す
- 最大負荷時のDB総接続数、接続待ち、長時間query、lock待ちを記録する
- Backendのscale out / inと再配置中も、描画機が自動再接続し最新状態へ復帰することを確認する

暫定合格値:

- APIエラー率1%未満。ただし認証・入力拒否は除く
- サーバー起因の位置点欠落1%未満
- 到着演出成功率95%以上
- 通常負荷で到着待ちp95 30秒以内
- 8時間で手動再起動、メモリ枯渇、表示停止がない

## セキュリティ・プライバシー試験

- IDだけ、期限切れトークン、別セッションのトークンによる操作を拒否する
- 位置・セッション作成・到着APIのレート制限を確認する
- 巨大JSON、不正座標、未来・過去時刻、重複点を安全に拒否する
- 到着証明の改変、共有、再利用、期限切れを拒否する
- 描画通信、運営画面、アプリログ、サーバーログに生緯度経度がないことを検索する
- 描画通信、運営画面、ログに写真、画像URL、オブジェクトキー、写真ハッシュがないことを検索する
- object bucketの公開アクセス、一覧取得、期限切れ署名URL、別セッション認証を拒否する
- 通常GPSの生座標がリクエスト処理後、通信断中、再接続後、停止後にDB・ログ・端末キューへ残らないことを確認する
- 写真撮影時GPSだけが写真再送データへ含まれ、成功・削除・期限で端末から消えることを確認する
- 到着後は`arrived`として選択画面を出し、追加同意後だけ`on_site`表示になることを確認する
- 写真ピン通信に写真、URL、生GPS、正確な時刻、セッションIDがないことを確認する
- Push本文に位置・写真・参加記号がなく、無効subscriptionを自動削除することを確認する
- DBバックアップ、アクセスログ、監視サービスの保持期間を確認する
- local / staging / productionで資格情報、DB、写真bucket、暗号鍵が分離されていることを確認する
- オブジェクトストレージのバージョニングが無効で、期限削除が写真にも適用されることを確認する
- 運営資格情報でのみ運営操作が可能で、操作履歴が残ることを確認する

## 公開判定

次をすべて満たした場合だけ、リアルタイム位置を利用して公開する。

- 全Must要件に対応する試験が合格している
- 重大障害と重大プライバシーリスクが未解決でない
- 本番端末・ネットワーク・会場でE2Eを3回連続完了している
- 最大負荷、8時間耐久、通信断、描画停止、削除試験が合格している
- 同意文、保存期間、問い合わせ先、当日責任者が承認済みである
- バックアップ描画と合成データ展示へ1分以内に切り替えられる
- 写真保存、非公開アクセス、EXIF除去、写真単位・期限削除試験が合格している
- 経路グラフが主要導線で現地確認され、誤経路を高信頼度表示しない
- PostgreSQL migration、バックアップ復旧、接続上限、直前releaseへのロールバック試験が合格している

未達の場合は、実位置の受付を無効化し、合成データまたは位置情報なしの代替体験で公開する。

## 2週間の技術成立判定

本制作へ入る前に、次の縦切り試作を実機・現地で完了する。通知利用率は判定条件に含めない。

| Gate | 2週間で確認すること | Go条件 | No-Go時の縮小 |
|---|---|---|---|
| G-01 | iOS/Androidで撮影、EXIF除去、写真＋撮影時GPS再送 | 対象実機で一連の保存・削除が成功 | 写真は端末保存のみ、サーバー写真機能を外す |
| G-02 | 最新GPS1件だけの送信、量子化、3D表示 | 過去点再送なし、p95 2秒以内、停止で消去 | リアルタイム位置を外し合成表現にする |
| G-03 | 写真2点からGraph経路を生成 | 禁止辺を使わず、不確実区間を低信頼度にできる | 経路を直線・抽象表現に縮小する |
| G-04 | 3D Map、Graph、座標版の位置合わせ | 主要基準点で許容誤差を決め、版不一致を拒否できる | 2D平面または限定エリアへ縮小する |
| G-05 | 写真ピンTTL、3件集計、削除減算 | 個別情報なしで生成・消去が再現できる | フォトスポットのみ、または機能を外す |
| G-06 | 到着QR、`arrived`、任意`on_site` | 追加同意と停止が実機で明確に選べる | 到着後は操作時だけの表示にする |

G-01〜G-06の結果、測定値、既知の制約、採用する縮小案を会議で承認してから3D表現の作り込みへ進む。
