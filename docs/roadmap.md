# ロードマップ

実日程と責任者は[プロジェクト計画・意思決定](project-plan.md)、公開条件は[試験計画・公開判定基準](test-plan.md)を正とする。

## Phase 0: 企画・承認準備

- [ ] 展示日、場所、対象者、開場時間を決める
- [ ] 企画、技術、表現、個人情報、会場、当日運営の責任者を決める
- [ ] 最大参加人数、予算上限、調達期限を決める
- [ ] 大学の施設、ネットワーク、個人情報、倫理、広報の申請経路を確認する
- [ ] 保存期間、同意しない人の体験、未成年者の扱いを決める

完了条件: 企画概要、Must要件、責任者、承認経路、未決事項の決定期限が合意されている。

## Phase 1: 技術検証

- [ ] キャンパス内で位置取得精度を実測する
- [ ] UnityとTouchDesignerで同一データを簡易描画する
- [ ] 匿名セッションと位置データモデルを決定する
- [ ] キャンパス座標から3D座標への変換を試す
- [ ] 画面ロック、アプリ切替、回線切替、権限拒否を実機で試す
- [ ] 到着時の色・記号による本人識別体験を試す
- [ ] 位置取得不能時のQRチェックポイント体験を試す

完了条件: 対象端末と主要導線で位置取得の成功率・欠測・電池・通信量を測定し、簡易3D再生と代替体験の成立可否を判断できる。成立しない場合は合成データ展示へ切り替える。

## Phase 2: MVP

- [ ] Next.js参加画面を作る
- [ ] Go位置受信APIを作る
- [ ] WebSocketで現在位置を配信する
- [ ] 簡易キャンパス上に複数参加者を描画する
- [ ] QR到着チェックインを作る
- [ ] 軌跡を10〜20秒で再生する
- [ ] 追跡停止、即時削除、保存期限削除を作る
- [ ] 到着証明の署名・有効期限・再利用防止を作る
- [ ] 再読込、複数タブ、通信断から状態を復元する

完了条件: QR参加から同意、追跡、到着、再生、停止、削除までの正常系と主要例外系を必須iOS・Androidで通せる。

## Phase 3: 展示統合

- [ ] 本番3D空間と視覚表現を制作する
- [ ] カメラ、音響、到着シーケンスを統合する
- [ ] 運営ダッシュボードを作る
- [ ] 障害時のフォールバックを用意する
- [ ] 機材を本番構成で連続稼働させる
- [ ] 主描画機とバックアップの二重再生防止を確認する
- [ ] 合成データによるフォールバックを用意する

完了条件: 本番機材で8時間連続稼働し、運営者だけで監視、受付停止、障害切替、終了を実施できる。

## Phase 4: 現地試験・公開

- [ ] 主要導線でE2Eテストを行う
- [ ] 複数端末の同時接続試験を行う
- [ ] 複数人同時到着を試す
- [ ] 同意、停止、削除の流れを確認する
- [ ] 設営・リハーサルを行う
- [ ] 60セッション相当の負荷と10人同時到着を試す
- [ ] ログ、バックアップ、期限削除に生位置が残らないことを確認する
- [ ] 会場安全、アクセシビリティ、連絡網を確認する

完了条件: 全Must要件と公開判定条件を満たし、本番構成でE2Eを3回連続完了し、未解決の重大リスクがない。未達時は合成データ展示へ切り替える。

## 未決事項

- 展示日と制作期限
- 想定同時参加人数
- 描画エンジンの最終選択
- 3Dモデルの制作方法
- 音響・照明の連携範囲
- 学内ネットワークと位置情報利用の許可
- 保存期間、データ管理責任者、問い合わせ先
- 対応OS・ブラウザと未成年者の扱い
- 予算、調達、当日担当者
