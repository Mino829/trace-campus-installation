### 配置方針の更新（2026-10-21、Issue #10）

上表のVercelとの不一致は10月15日時点の記録。技術構成は[インフラ方針](infrastructure-database-decision.md)でCloudflareサイトWorker（静的Webと`/api/backend/*`中継）＋Google Cloud東京（Cloud Run、Cloud SQL for PostgreSQL 17、非公開Cloud Storage）へ統一した。Cloudflareで通信を処理するため「全データ・全処理が東京」とは記載しない。調査用D1/KVを本番へ流用しない。Vercel案は不採用、AWS案は承認で変更が必要になった場合の再検討先とする。

これは企画の技術選択であり、大学の提供者・地域・個人情報承認や公開許可ではない。未了: Cloud Runの安全な公開経路とWorkerからのE2E、描画WSSの認証経路、Cloud SQLの可用性・接続上限/負荷試験、7日上限のバックアップ/PITRと保存期間、独自ドメイン/DNS/TLS/WAF・監視の実作業者、5,000円上限内の費用見積もり。課金責任者はMino829、技術・個人情報責任者は未決。未承認なら実データを受け付けず、合成データ展示または公開見送りとする。

## 最小チームと縮小順

最低でも、企画・進行、Web/Backend、3D/表現、マップ/現地検証、個人情報・当日運用の責任を割り当てる。兼任は可能だが、3D制作とBackend（地点解決・経路生成）を同じ一人の同じ期間へ集中させない。

遅延時は、(1) Web Pushを外して画面内の撮影案内へ置き換え、(2) 経路再生を10〜20秒の全体再生から簡易表示へ縮小、(3) 3Dを限定エリアまたは2Dへ縮小、(4) サーバー写真保存を外して端末保存のみ、の順で縮小する。写真を撮って思い出を残す体験、本人による閲覧・削除、原写真を公開しないことは最後まで維持する。リアルタイムGPS・`on_site`・写真ピン・フォトスポット集計はGPS不使用化により廃止済みであり、縮小順の対象から外れた（2026-10-26、#23）。
