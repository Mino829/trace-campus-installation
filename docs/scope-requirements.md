# スコープ・要件定義

## 文書の使い方

各要件にはID、優先度、受け入れ条件を付ける。実装や試験ではIDを参照し、変更時は理由、影響、承認者を記録する。

- `Must`: 公開に必須
- `Should`: 原則実装するが、代替策を承認できる
- `Could`: 時間と予算に余裕がある場合

## 前提と暫定値

| 項目 | 暫定値 | 確定条件 |
|---|---|---|
| 同時追跡 | 50セッション | 実地予測と負荷試験で確定 |
| 1セッションの追跡上限 | 6時間 | 展示導線と電池試験で確定 |
| 位置取得間隔 | 5秒を初期値 | 精度・通信量・電池試験で調整 |
| 到着演出 | 15秒を初期値 | 10〜20秒の表現試験で確定 |
| 対応言語 | 日本語、英語 | 来場者要件で確定 |
| 本番保存先 | 公開環境の単一DB | 配置設計と大学承認で確定 |
| 生位置の保持 | 24時間以内を提案 | 個人情報責任者が公開前に承認 |

## 対象範囲

### 対象

- QRからの参加、説明、同意、位置権限取得
- 追跡状態表示、停止、即時削除
- 位置点の検証、保存、座標変換、抽象化
- 現在位置と到着軌跡のリアルタイム描画
- 到着キューと運営操作
- 監視、障害復旧、合成データへのフォールバック

### 対象外

- 個人アカウント、SNSログイン、ランキング
- 正確な屋内階層判定
- 行動分析や個人プロファイリング
- 無期限の軌跡アーカイブ
- 参加端末への専用アプリのインストール

## 機能要件

| ID | 優先 | 要件 | 受け入れ条件 |
|---|---|---|---|
| FR-001 | Must | 取得目的、項目、表示方法、保存期間、停止・削除方法、問い合わせ先を位置権限要求前に表示する | 未同意では位置APIを呼ばずセッションを開始しない |
| FR-002 | Must | サーバーが有効な同意文バージョンを配信する | 旧版・未知の版によるセッション作成を拒否する |
| FR-003 | Must | 匿名セッションと推測困難な参加トークンを発行する | IDだけでは状態取得、送信、停止、削除ができない |
| FR-004 | Must | 参加中画面に追跡状態と最終送信時刻を表示する | 位置更新停止を30秒以内に参加者が認識できる |
| FR-005 | Must | 有効な位置点を指定間隔で送信する | 位置権限許可時に対象端末で有効点を取得できる |
| FR-006 | Must | 通信断時に未送信点を端末内で一時保持する | 最大件数・時間を表示し、期限超過点は送信しない |
| FR-007 | Must | 参加者がいつでも追跡を停止できる | 停止受付後の位置点を保存しない |
| FR-008 | Must | 参加者が現在のセッションデータを削除できる | 削除後はトークンを無効化し関連データが検索できない |
| FR-009 | Must | 到着地点の有効なQR/NFCだけで到着を受け付ける | 期限切れ、改変、別会場の到着証明を拒否する |
| FR-010 | Must | 到着受付と同時に追跡を停止する | 到着時刻より後の位置点を保存しない |
| FR-011 | Must | 到着後に待ち状態と予想順を参加端末へ表示する | 再接続後も到着・再生状態を復元できる |
| FR-012 | Must | 参加端末と展示に同じ非識別の色・記号を表示する | 参加者がセッションIDを見ず自分の演出を識別できる |
| FR-013 | Must | 軌跡再生をスキップして終了できる | スキップ後に待ち行列から除外される |
| FR-014 | Must | 到着キューを一度に一つの主描画機が処理する | 二重再生が発生しない |
| FR-015 | Must | 運営者が受付停止、再生スキップ、フォールバック切替を行える | 権限のある運営端末だけが操作でき履歴が残る |
| FR-016 | Must | 描画接続時にスナップショットから状態を復元する | 再起動後、目標時間内に現在表示へ復帰する |
| FR-017 | Must | GPS・通信・サーバー障害時に合成データ表現へ切り替える | 判断後1分以内に展示を継続できる |
| FR-018 | Should | QRチェックポイントで位置取得不能時の代替軌跡を作る | GPSを許可しなくても代替参加を完了できる |
| FR-019 | Should | 日本語と英語を切り替える | 同意内容と主要操作が両言語で一致する |
| FR-020 | Could | NFC到着に対応する | QRと同じ到着検証・冪等性を満たす |

## 非機能要件

| ID | 優先 | 要件 | 受け入れ条件 |
|---|---|---|---|
| NFR-001 | Must | 最大50追跡、60相当の負荷に耐える | 30分試験でエラー率1%未満、データ欠落1%未満 |
| NFR-002 | Must | 有効位置受信後の展示反映を速くする | p95で2秒以内。端末の取得間隔は含めない |
| NFR-003 | Must | 到着から再生開始までの待ち時間を抑える | 通常負荷でp95 30秒以内 |
| NFR-004 | Must | 描画切断から自動復旧する | ネットワーク復旧後10秒以内に再接続を開始する |
| NFR-005 | Must | 8時間連続稼働する | メモリ枯渇、手動再起動、表示停止がない |
| NFR-006 | Must | 通信をTLSで保護する | 公開経路がHTTPS/WSSのみである |
| NFR-007 | Must | 生位置を描画・運営ログへ渡さない | 通信・ログ検査で緯度経度が検出されない |
| NFR-008 | Must | 対象ブラウザを明示する | 試験計画の必須端末ですべてMust要件に合格する |
| NFR-009 | Must | アクセシブルな主要操作を提供する | キーボード、読み上げ、200%拡大で開始・停止・削除可能 |
| NFR-010 | Should | 1セッションの通信量と電池消費を抑える | 実地試験結果を記録し、参加前の注意へ反映する |

## プライバシー・セキュリティ要件

| ID | 優先 | 要件 | 受け入れ条件 |
|---|---|---|---|
| PS-001 | Must | 氏名、学籍番号、メール、広告ID、端末固有IDを収集しない | DB、ログ、解析ツールの項目監査に合格する |
| PS-002 | Must | キャンパス外の位置点を保存しない | 境界内外の試験点で期待どおり判定する |
| PS-003 | Must | 表示位置を量子化・オフセットする | 描画出力から生座標を復元できない設定である |
| PS-004 | Must | データ種別ごとの削除期限を自動適用する | 期限超過データの削除ジョブ試験に合格する |
| PS-005 | Must | 到着証明の偽造・再利用を防ぐ | 改変、期限切れ、他会場、再送の試験に合格する |
| PS-006 | Must | 参加・描画・運営の認証を分離する | 各資格情報で範囲外APIを実行できない |
| PS-007 | Must | レート制限と最大入力サイズを設ける | 過剰送信が429または接続制限になる |
| PS-008 | Must | 実データを開発・デモへ転用しない | フォールバックと試験が合成データで動く |

## 運用要件

| ID | 優先 | 要件 | 受け入れ条件 |
|---|---|---|---|
| OPS-001 | Must | 開場・閉場チェックリストを運営者が実施する | 実施者、時刻、結果が残る |
| OPS-002 | Must | 当日責任者と障害連絡網を定める | 運営場所から参照できる |
| OPS-003 | Must | リアルタイム受付を即時停止できる | 操作後、新規セッションを拒否し案内を表示する |
| OPS-004 | Must | バックアップ描画と合成映像を用意する | 本番機材で切替リハーサルに合格する |
| OPS-005 | Must | 終了時に追跡停止と削除ジョブを確認する | 閉場手順に記録が残る |

## 変更管理

要件変更時は、変更理由、影響する要件ID、データ・同意文への影響、試験変更、承認者をプルリクエストまたは決定記録に残す。Must要件を削除または緩和する場合は、展示責任者と該当領域の責任者による承認を必要とする。
