# スコープ・要件定義

> 2026-10-26改訂（#23）: GPS（位置情報）の利用を廃止し、写真地点を参加者が3Dマップで選んだチェックポイント地点のみとする仕様へ改訂した。新規写真バイト列は参加者端末だけに保存し、Backendには経路用メタデータを保存する方針を設計目標として追記した。写真保存・削除・同意に関わる既存Mustの変更は未承認であり、実装済み・公開可能を意味しない。

## 文書の使い方

各要件にはID、優先度、受け入れ条件を付ける。実装や試験ではIDを参照し、変更時は理由、影響、承認者を記録する。

- `Must`: 公開に必須
- `Should`: 原則実装するが、代替策を承認できる
- `Could`: 時間と予算に余裕がある場合

以下の写真関連行は、既存IDと優先度を残したまま端末限定方式での変更案を併記する。括弧内の「承認待ち」「設計目標」は既存Mustを変更済み・達成済みとするものではない。変更承認までは従来の写真送信・非公開Cloud Storage保存・本人照会/削除・期限削除の契約を維持し、新方式を実データ受付に用いない。

## 前提と暫定値

| 項目 | 暫定値 | 確定条件 |
|---|---|---|
| 同時セッション | 50セッション | 実地予測と負荷試験で確定 |
| MemorySession TTL | 6時間（開発側既定） | 展示時間と容量試験、大学承認で確定 |
| `delete_after` | MemorySession失効後24時間（開発側既定）。新規分は写真メタデータ・チェックポイント地点・経路・削除冪等性記録を対象とする設計目標。既存のCloud Storage写真は従来の`deleteAfter`まで保持し、本人削除または期限削除で消す | 個人情報責任者が公開前に承認。既存データを無断で前倒し削除しない |
| APIセキュリティログ | 30日（提案値） | 大学承認待ち。確定まで公開判定を完了させない |
| DBバックアップ | 最大7日（提案値） | 大学承認待ち。確定まで公開判定を完了させない |
| 到着演出（経路再生） | 全体10〜20秒を初期値。区間の長さに比例配分し、写真地点で少し停止 | 10〜20秒の表現試験で確定 |
| 対応言語 | 日本語、英語 | 来場者要件で確定 |
| 1セッションの写真 | 12枚 | 実機の通信量・容量試験で確定 |
| 写真の公開表示 | 行わない | 将来実施時は別同意とモデレーションを設計 |

位置情報（GPS）の取得・保持は行わない（2026-10-26決定、#23）。写真地点は参加者が選んだ`checkpointId`のみで、座標・対応ノードID・グラフ版の解決はBackendが行い、参加端末は座標を送らない。

新規写真の画像バイト列（加工画像・縮小画像を含む）はサーバーへ送らず、参加者のブラウザ内（IndexedDB等）にのみ保存する設計目標。Backendには写真ID、撮影時刻、`checkpointId`など経路再構成に必要なメタデータだけを送る。端末の写真が消えた場合、サーバーから復元できず、別端末への引き継ぎもできない。ブラウザ保存領域は容量制限・OS/ブラウザによる消去があり、端末を開かない間の自動消去は保証しない。本人による写真アプリ等への手動保存を案内する。旧方式でCloud Storageに保存済みの写真は本人資格による照会・削除と既定の`deleteAfter`期限削除を維持する。新規方式のFrontend/Backend実装と既存Mustの変更承認は未完了。

## 対象範囲

### 対象

- QRからの参加、説明、同意、カメラ権限取得
- Web App内での写真撮影、向き補正・EXIF除去・縮小、本人用写真ストーリー（新規画像バイト列は端末保存のみを設計目標とし、未実装）
- 参加状態の表示、停止、即時削除
- 参加者が3Dマップで選んだチェックポイント地点（`checkpointId`）とCampusGraph最短経路による経路再構成・再生
- 展示ブースで投影・定期更新する署名・期限付きQRによる到着と、到着後の完了状態・自動削除予定日時の表示
- 30分ごとの撮影リマインダー（Web Push、通知なしでも参加可）
- 監視、障害復旧、合成データへのフォールバック

### 対象外

- 個人アカウント、SNSログイン、ランキング
- 位置情報（GPS・Geolocation・撮影時GPS）の取得・送信・保持（2026-10-26決定、#23）
- LivePresenceSessionの新規発行、位置送信、`on_site`（廃止、#23）
- ExperienceLink・色・記号・`display_alias`による照合表示（廃止、2026-10-26決定、TRACE_F#10）
- 行動分析や個人プロファイリング
- 無期限の軌跡アーカイブ
- 参加端末への専用アプリのインストール
- 写真原画像の公開スクリーン表示、友人間共有、SNS投稿
- 自動Vlog動画生成、写真内容の人物・文字・物体分析
- カメラを許可しない人向けの代替参加（展示の観覧はできる）
- 同じ人の二重参加の防止（もう一度参加してもよい）

| NFR-017 | Must | DB接続数を接続プールとBackend最大インスタンス数で制御する | 最大負荷時もDB接続上限の予約枠を消費せず、接続枯渇が発生しない |
| NFR-018 | Must | local、staging、productionを分離する | 本番資格情報・参加者データがlocalまたはstagingへコピーされない |

## 変更管理

要件変更時は、変更理由、影響する要件ID、データ・同意文への影響、試験変更、承認者をプルリクエストまたは決定記録に残す。Must要件を削除または緩和する場合は、展示責任者と該当領域の責任者による承認を必要とする。

新規画像バイト列の端末限定保存は方針の設計目標であり、新規写真用Frontend/Backendは未実装。写真送信・保存・本人閲覧・削除と同意に影響する既存Must（FR-001/002/008/021/022/023/026/027、PS-004/009/010/012、NFR-011/012/013）の緩和は、展示責任者および該当領域責任者の承認待ちである。FR-030（Should）の手動保存の位置付けも同時に再審査する。承認前に既存Mustが緩和済みとして公開判定せず、同意文の正本も決めない。
