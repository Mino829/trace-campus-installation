# プライバシー設計（完成版）

- 更新日: 2026-11-06
- 実装基準: Frontend `be94bd2`、Backend `6b87961`

会期は終了した。新規GPS取得・送信と新規画像クラウド保存を行わない完成版を記述する。コードで同意を配信できること、過去の配備・smoke記録、大学の正式承認、現在の停止・全削除は別であり、承認・清掃・費用停止の実績は未確認。本改訂は保持期限・既存同意・公開承認を変更しない。

氏名のないランダムIDでも、地点・時刻・経路・写真から本人や第三者の行動を推測できる。「匿名ID」は完全な匿名情報を意味しない。

## 原則

- 参加・撮影・通知は本人の選択。参加者のGoogleログイン、GPS許可は要求しない。カメラ拒否時にも観覧を強制参加にしない。
- 新規参加は`/log`でGo公開設定の本文・版・言語を提示し、明示同意後にMemory作成成功を確認する。設定/作成失敗を端末だけの参加成功に偽装しない。
- 新規写真画像は端末IndexedDBのみ。地点は本人が固定Graphから選ぶ自己申告で、Goには`clientPhotoId/checkpointId/capturedAt`のみを送る。画像・GPS・EXIF・画像URL/ハッシュ/寸法を送らない。
- `/display`は画像なしの経路表現。公開スクリーンに写真原画像・正確な時刻・内部IDを表示しない。作品閲覧は本人端末で到着前から可能で、参加/到着/予約/通知を変えない。
- 参加停止・通知解除・画像削除・サーバーmetadata削除・全体削除を区別する。停止後も各`deleteAfter`まで本人閲覧・削除を維持する。
- 旧Memory/Liveは別資格・期限を保持し、旧写真の本人閲覧・削除、旧Liveの状態・停止・削除と期限清掃を残す。GPS書込み・on_site位置継続を復活させない。
- 実データを開発、合成fallback、機械学習、広報/SNS、研究、再展示へ無断転用しない。

## データ一覧と暫定保持期間

見出しは参照用に維持する。実際の期限は既存Sessionの`expiresAt/deleteAfter`と適用済み同意が正本。会期終了を理由に一括延長・前倒ししない。会期中構成には「参加6時間＋その後24時間」の配備記録があるが、全環境・全Session・正式承認済みの保証ではない。

| データ | 保存先・用途 | 保持/削除の境界 |
|---|---|---|
| 新規写真JPEG | 参加端末IndexedDB、本人一覧・作品画像 | 本人操作で消去。ページを閉じた端末での期限自動消去は保証しない |
| 端末の写真metadata・旧開発GPS記録 | IndexedDB、本人端末の記録 | 旧記録は保持し再送しない。参加写真消去と旧開発記録全消去を混同しない |
| 新規写真のclient ID・地点・撮影時刻、再構成経路 | Go/Cloud SQL、本人閲覧・到着描画 | 写真単位/Memory削除、各`deleteAfter`清掃。削除client ID fenceはMemory期限まで |
| Memory/旧Live・同意版/時刻・期限 | Cloud SQL、参加/本人認証 | 独立した`deleteAfter`。停止・失効は閲覧/削除期限の終了ではない |
| 参加者Bearer・本人が同意した本文 | 同じブラウザのlocalStorage | 本人削除/資格無効/期限検知で処理。別ブラウザへ自動引継ぎなし |
| 到着・再視聴・主描画lease | Cloud SQL、FIFO/描画復旧 | Session所有の記録はMemory削除/清掃対象。公開再生IDと内部本人IDを分離 |
| 旧クラウド写真・旧GPS由来アンカー/経路 | 非公開GCS/Cloud SQL、旧本人閲覧 | 新規登録・署名PUT発行/再発行・complete停止。各`deleteAfter`まで本人権利を保持 |
| 旧最新位置 | Goメモリの旧実装キャッシュ。新規書込み・現行描画への配信なし | TTL・停止・削除で消去。DB保存しない |
| Push endpoint・購読鍵 | Cloud SQLに暗号化、Go30分通知 | 方針別到着、停止、解除、期限、削除、運営全通知stop、provider無効化で消去 |
| 運営資格・監査 | DBに資格/hash、actor照合hash等 | 資格2分、操作監査24時間。hashでも照合可能で匿名化ではない |
| 描画/Google資格 | ブラウザメモリ、認証 | URL/永続保存/QR/ログ禁止。displayToken2分、WSSには別接続期限あり |
| 削除receipt・proof消費fingerprint | DB、再送/復活防止 | 内容と所有関係に応じ最大24時間かつMemory期限内等の実装契約。全て一律匿名receiptとは説明しない |
| API/edgeログ・DB backup/PITR | 各提供者、障害/復旧 | 実設定・承認・世代消去は未確認。旧案のログ30日・backup7日を確定値としない |

サーバー期限到来は清掃成功の証拠ではない。端末IndexedDB、OSへ保存した作品/写真、クラウドmetadata、旧GCS、backupを別々に扱う。Goは参加端末画像を検証・復旧・遠隔消去できない。

## 同意画面に含める内容

- 写真は端末内、自己申告の撮影場所・時刻はサーバーへ送ること。GPSを取得せず、実歩行を測定した経路ではないこと。
- 作品の目的、公開スクリーンの画像なし経路表現と撮影され得ること、第三者の顔/名札/授業資料/撮影禁止場所への注意。
- 参加/削除期限、停止と削除の違い、端末写真とサーバー情報の削除方法、閉じた端末の自動消去保証がないこと。
- 同じブラウザで参加を復元するため資格を保存すること。ブラウザデータ消去・容量不足・別端末/プライベートブラウズで参加/画像を失い得ること。
- 通知は別の明示同意とOS/ブラウザ許可が必要、30分のみ、遅延/重複/未達があり得ること。許可しなくても参加・撮影・作品閲覧・削除ができること。
- 到着で通知を止める従来方針か、到着後も参加期限まで継続する新方針かを同意版で明確にすること。
- 利用提供者、処理/保存地域、ログ/backup、問い合わせ先・未成年者対応。会期中の「301ブーススタッフ」を終了後常設窓口と断定しないこと。

Backend公開設定が本文の正本。参加後も同意した本文を端末から確認する。対応する版だけ参考英訳を併記し、英語切替で参加資格を作り直さない。既定草案で受付を開かず、本文変更は新しい版とする。

### 到着後の通知と既存同意

`TRACE_PUSH_AFTER_ARRIVAL_CONSENT_VERSION`は現行Memory同意版との完全一致と、明示的な非既定の新本文/版を要求する。その版で**新規作成されたMemoryだけ**に継続方針を保存する。既存行はfalseのまま、設定後付け・購読PUT/PATCH・Frontend表示だけでは昇格しない。以前到着時に消した購読を復元せず、到着だけで購読を作らない。通知許可は引き続き別に必要。API・dispatcher・cleanupの対応版とmigration020を揃えることが必要だが、コード検査は本文の意味・大学承認を判定しない。

## 停止・撤回・削除

| 本人/運営の操作 | 消えるもの・残るもの |
|---|---|
| Memory参加停止 | 新規参加操作を終端化し購読/予定を消去、queued/playingを除外。期限は変えず本人閲覧・削除を保持。端末画像/全metadata削除とは別 |
| 通知解除 | 購読/予定/鍵を消去。参加・写真・到着は停止しない。単純解除と再開不能な参加停止を区別 |
| 写真単位削除 | 端末画像の消去と対応Go metadata削除をそれぞれ扱う。サーバー削除失敗を成功扱いせず再試行/期限清掃へ。旧GCSは画像消去完了までdeleting保持 |
| Memory全削除 | 本人所有metadata・経路・到着・購読等を削除し、端末の対応写真も本人画面で消去。サーバー応答だけで全端末/OS保存画像消去を保証しない |
| 旧Live停止/削除 | 旧Live自身のBearer/期限で操作。Memoryだけ消しても旧Liveが削除済みとはしない |
| 両方を削除 | Memory Bearer、旧Live token、同じIdempotency-Keyで独立結果を確認。部分成功/通信失敗では残る資格と再送キーを保持 |
| 期限清掃 | 対応版API/清掃jobがサーバー期限データ・旧画像を削除。端末閉鎖中の画像消去とは別 |
| 運営受付close / 全通知stop | 別々の永続制御。本人削除/API/清掃を撤去する操作ではない |

トークンを失った場合、氏名などを取らないため別端末から本人を再識別して削除することは困難。自動期限清掃の時期・障害時の遅延・問い合わせ方法を説明し、期限を理由に清掃成功を仮定しない。新規参加資格を作り直して旧写真を自動移行しない。

## 表示・再識別対策

描画WSSは写真画像/URL、PhotoMoment ID、Memory/Live ID、GPS、本人Bearer、色/記号による個人照合情報を送らない。公開再生IDに対して`pathNodeIds`と`photoCheckpoints`（地点ID・撮影時刻）等を送るため、地点・順序の漏えいリスクは残る。画面にはID・正確な時刻を表示せず、本人専用作品や保存JPEGと公開スクリーンを分ける。写真ピン・フォトスポット・リアルタイム位置の量子化表示は現行機能ではない。

## 写真撮影・保存

- `preparePhoto`は向き補正、長辺1280px以内のJPEG（品質0.8）へ再エンコードし、元EXIF/GPSを画像・記録へコピーしない。画像は端末保存であってBackendの新規画像検証を通るものではない。
- 最大12枚のmetadata契約とローカル保存成功は別。到着後も有効Memoryでは端末撮影可能だが、新しいmetadataを到着後に追加送信しない。端末作品とGo展示が常に同じ写真集合とは限らない。
- 端末の画像保存/OSへのダウンロードをサーバーbackupと呼ばない。OSに保存した写真/作品の消去はIndexedDB消去とも別。
- 旧ready画像は本人認証と短期署名URL（5分と`deleteAfter`の早い方）で取得する。旧bucketの公開/一覧は禁止。
- 旧署名PUTの残存期限にはゼロバイトfenceを置き、期限後に再消去する。画像/fenceが残る間はAPI/清掃のGCS設定・権限を外さない。

## ログ・外部サービス

参加Bearer、Google/運営/描画資格、Edge/署名/暗号化鍵、写真バイト列・URL・object key・GPS・raw QR proofを通常ログへ出さない。IP/User-Agent等を扱うCloudflare・Google Cloud・Google本人確認・Push providerを区別し、DB/旧bucketが東京だから全処理が東京とは説明しない。参加者情報を行動解析・広告・録画へ無断転用しない。実ログ保持とアクセス権・backup復元時の再削除は別途確認する。

## インシデント対応

漏えい・誤表示・期限超過・不正アクセスが疑われる場合、対象環境を特定し新規受付/必要な通知を別々に停止、必要最小限の証跡を保全して責任者へ連絡する。本人権利・旧画像/fence・清掃を壊す全資源削除を先行しない。影響・大学規程・連絡/再開条件は権限のある担当者が判断する。[終了手順](deployment-operations.md#終了手順)も参照。
