# プライバシー設計

本資料は2026-10-26のGPS不使用・写真地点自己申告決定（#23）と、追加の写真画像は端末内だけに保存する開発方針を扱う。サーバーへは匿名セッションに結び付く写真ID・`checkpointId`・撮影時刻など経路用メタデータだけを送る。現行Backendのクラウド写真契約は未移行であり、新方式の実データ受付は同意・要件・旧写真削除の承認とFrontend/Backendの実装整合まで停止する。地点と時刻の組み合わせも行動を推測し得るため、画像を送らなくても保護が必要である。

氏名を取得しなくても、写真や地点と時刻の組み合わせは本人、第三者、場所、行動を推測できる可能性がある。本資料では「匿名ID」を直接識別子を持たないランダムIDという意味で使い、写真データ自体が完全な匿名情報であるとは扱わない。

個人情報責任者・技術責任者・企画責任者はMino829に確定済み（2026-10-26）。大学の個人情報審査と展示責任者によるMust変更承認は別途必要である。

## 原則

- 参加は完全に任意とする
- カメラ利用・端末内画像の保存・写真地点と時刻のサーバー送信前に、それぞれの目的、保存先、公開範囲、削除できる範囲と端末画像の消失リスクを説明する。GPSは取得しない
- 個人名、学籍番号、メールアドレスを収集しない
- 匿名IDは作品参加以外のデータと結合しない
- 参加者はいつでもセッションを削除できる
- セッション失効後も`delete_after`までサーバーの状態・写真メタデータを本人が照会・削除できる。端末画像は同じブラウザの保存領域が残る場合に限り表示できる
- セッションは`MemorySession`単独とする。リアルタイム位置用の別セッション・別トークン・別同意（LivePresenceSession、ExperienceLink）は廃止した（2026-10-26決定、#23）
- 座標は参加者が選んだチェックポイント地点としてだけ扱い、GPS由来の座標を保存しない
- 展示では写真地点と再構成経路を抽象表現で描き、セッションID・氏名・正確な時刻を公開画面へ出さない
- 保存期間終了後にサーバーの写真メタデータ・地点・経路を期限削除する。端末内画像はWeb Appが次に開かれた際に期限を検知して消すが、端末を開かない間の自動消去は保証できない
- 実データを開発、デモ、フォールバック、機械学習へ転用しない
- 研究、論文、広報、SNS、翌日以降の展示へ利用する場合は、当初目的と分けて審査・説明する
- 新規写真の画像は参加端末のWeb App内だけに保存し、Backend、公開スクリーン、運営画面、通常ログへ画像・画像URL・復元性の高い特徴を送らない。旧サーバー写真の本人閲覧・削除・期限清掃は既存セッションの`deleteAfter`まで維持する
- 写真内容を人物・文字・物体の分析やプロファイリングに使わない

## データ一覧と暫定保持期間

保持期間は公開前に大学の個人情報責任者が承認する。以下のサーバー保持期間は提案値であり、承認前に確定値として同意画面へ出さない。開発側既定のMemorySession TTL 6時間、`delete_after`=失効後24時間を写真メタデータ・地点・経路・削除冪等性記録に適用する。端末画像はローカル削除操作時または期限検知時に消すが、閉じたブラウザの実行時刻やブラウザによる早期消去は保証できない。APIセキュリティログ30日・DBバックアップ最大7日は提案値のまま大学承認待ち（#9）。

| データ | 用途 | 暫定保持 | 削除 |
|---|---|---:|---|
| 加工済み写真（新方式） | 本人用写真ストーリー | 同じブラウザのIndexedDB。端末の容量・ブラウザ消去で早期に失われ得る | 本人の操作時と次回起動時の期限検知でWeb Appが削除。閉じたままの端末や明示保存された複製の消去は保証しない |
| 写真メタデータ（写真ID・`checkpointId`・撮影時刻） | 経路再構成・到着展示 | サーバーにMemorySessionの`delete_after`まで（提案: TTL 6h+24h） | 写真単位・セッション削除・期限ジョブ |
| チェックポイント地点（`checkpointId`とその解決結果） | 経路再構成 | メタデータと同じ`delete_after`まで | 写真メタデータと同時に削除 |
| 再構成経路（点ID列とグラフ版） | 到着時の再生 | メタデータと同じ`delete_after`まで | 同上 |
| 到着・再生イベント | キュー、演出復旧 | MemorySessionの`delete_after`まで | 同上 |
| Web Push購読情報 | 撮影リマインダー（30分間隔のみ） | 到着・解除・期限の最早時点まで | 自動・手動解除 |
| 写真メタデータのオフライン再送待ち | 通信復旧後の登録 | 端末内。送信期限まで | 成功、本人削除、期限検知時に削除 |
| 参加トークン | 本人の状態取得・閲覧・削除 | 端末の`localStorage`に、本人の削除または`delete_after`まで | 削除・期限を検知した時点で端末から消去 |
| 同意版・同意時刻 | 同意確認 | セッションと同じ | 同上 |
| APIセキュリティログ | 障害・不正調査 | 30日以内を提案 | ローテーション。生位置を含めない |
| DBバックアップ | 障害復旧 | 最大7日を提案 | 世代削除。アクセスを技術責任者に限定 |
| 削除冪等性記録 | 削除要求の安全な再送 | 24時間以内。写真・地点・経路と同一期間で一緒に消す | 位置・軌跡を持たず期限削除 |
| 非個人の運用集計 | 展示評価 | 企画責任者が公開前に定める期間 | 少人数・経路・正確な時刻を含めない |

GPS廃止に伴い、旧仕様で取得したデータは次のように扱う（2026-10-26決定、#23、読み取り契約はTRACE_B#30）。

- 新規の`LivePresenceSession`は発行しない。既存の旧Sessionは本人資格での状態照会・停止・削除と各`deleteAfter`までの期限清掃のみを残す。位置送信・`on_site`エンドポイントは廃止する
- 旧GPSデータ（旧撮影時GPS・旧描画位置イベント・旧写真の緯度経度列）は前倒し削除せず、各対象セッションの`deleteAfter`まで保持した上で期限削除する。読み取りは旧描画位置イベント・写真の緯度経度列に限り認める
- 旧クラウド写真（既にサーバーに保存された画像）は、新方式への切替時に端末へ自動移行できない。旧本人取得・個別削除・期限清掃を各`deleteAfter`まで維持し、既発行アップロードURLの失効と残存オブジェクトの消去を確認してから旧bucketや鍵を廃止する。前倒し削除や新方式で復元可能との説明をしない

## 同意画面に含める内容

従来の`2026-memory-photo-no-gps-draft-1`はサーバーへの写真保存を前提とする開発草案であり、新方式に再利用しない。新しい版・本文、/logの同梱文とBackend配信本文のどちらを正本にするか、日本語・英語の整合は#9で関係者と相談・大学審査後に決定する。承認済みの同意が得られるまで新方式の実データ受付を開かない。参加条件のカメラ権限は写真撮影と到着QR読取のためである。

- 作品の目的
- カメラの許可が参加の条件であること
- 端末で扱う情報: 写真画像（同じブラウザだけ）、写真ID、撮影時刻、選んだ`checkpointId`
- サーバーへ送る情報: 写真ID、撮影時刻、`checkpointId`、匿名セッション。画像バイト列・画像URL・EXIF・画像のハッシュ/寸法は送らない。GPS・氏名・学籍番号・メールアドレスも収集しない
- 展示での利用方法
- 保存方法: 参加者が3Dマップで選んだ地点を結ぶ最短経路を再構成し、到着時に再生すること
- サーバーメタデータの`delete_after`と、端末画像の次回起動時の期限清掃は別であること。ブラウザ消去・端末紛失・別端末への移動では画像を復元できず、Web Appを開かない間の即時消去や写真アプリへ書き出した複製の消去は保証しないこと
- 問い合わせ先
- 通知（30分間隔の撮影リマインダー）は許可しなくても参加できること、OS・ブラウザにより遅延・停止する可能性と解除方法
- 参加トークンを同じブラウザに保存すること。失うとサーバーの個別削除ができず、サーバー側は`delete_after`に自動消去する一方、端末画像はWeb Appが当該データを参照できる場合に限り消去できること
- サーバー・外部委託先・国外移転がある場合の説明
- 未成年者に関する参加条件
- 新規写真の画像は本人端末だけにあり、公開スクリーン・Backendには送らないこと。旧クラウド写真の保持・削除経路は別に説明すること
- 他人の顔、名札、個人情報、授業資料、撮影禁止場所を写さない注意
- 参加者が写真アプリへ明示的に保存した複製は、Web Appやサーバーの削除操作で消えないこと

同意文はバージョンごとに変更不能な形で保存する。参加者が同意する前にブラウザのカメラ権限ダイアログを表示しない。

## 停止・撤回・削除

セッションは`MemorySession`単独である。

- セッション削除: BackendはMemorySession・写真メタデータ・経路・地点・到着イベント・Push購読・トークンハッシュを本人Bearerで削除する。Web Appは対応する端末内画像と再送待ちを別に消し、両方の成功/失敗を区別して伝える
- 写真単位削除: Backendはメタデータ・経路参照・地点を更新し、Web Appは同じブラウザの画像を削除する。旧サーバー写真は旧オブジェクトの消去を確認してから成功とする
- 保存期限削除: Backendは`delete_after`にメタデータ・経路・地点・削除冪等性記録を定期清掃する。端末画像は次回起動時にWeb Appが削除し、サーバーからの即時強制削除はできない
- 旧LivePresenceSessionの削除: 旧用トークンでの照会・停止・削除と`deleteAfter`までの期限清掃のみ認める

参加中・失効後の`delete_after`まで、本人はサーバー側メタデータを削除できる。Backendの204は端末画像の消去証明ではない。別ブラウザ/端末やプライベートブラウズ終了で資格情報を失った場合、サーバー側は`delete_after`に自動消去されるが、端末内画像の有無や消去をサーバーが確認することはできない。端末内の保存領域を消す方法と問い合わせ先を同意文に明記する。

## 表示・再識別対策

- 公開描画へ写真、画像URL、復元性の高い画像特徴、生座標、生GPSを送らない。描画PCへ渡すのは経路の点IDの並び、グラフ版、写真ごとの点IDと撮影時刻だけである（2026-10-26決定、#23）
- 画像から抽出した主要色等の特徴は新方式ではサーバーへ送らない。将来追加する場合は個人情報審査・要件変更を別に行う
- 正確な時刻（秒単位）、入口名、建物名、連続するセッションIDを公開画面へ出さない
- 自分の演出の識別に氏名や連番、色・記号照合を使わない
- 順位・待ち時間・集合表現への参加を示す表示をしない
- 観覧者による画面撮影が想定されることを同意文または会場掲示で伝える

旧仕様の量子化・セッション固定オフセット・平滑化・個別ピン・フォトスポット集計（FR-031〜033、PS-014相当）は、表現自体が廃止されたため削除した（2026-10-26決定、#23）。

## 写真撮影・保存

- 撮影前と撮影画面に第三者・撮影禁止情報への注意を表示する
- Web Appが向き補正・EXIF除去・縮小・再エンコードした画像を同じブラウザのIndexedDBへ保存し、画像が保存できなければ撮影完了としない
- 画像バイト列・画像URL・ハッシュ・寸法をBackendへ送らない。送るのは匿名セッションに属する写真ID・地点ID・撮影時刻のメタデータのみ
- IndexedDBは端末の容量不足・ブラウザ消去で失われ得る。別ブラウザや別端末で画像を復元できず、写真アプリへ書き出した複製はWeb Appの削除対象外
- 既存の非公開bucketに残る旧写真の本人照会・削除と期限清掃は各`deleteAfter`まで維持する
- 自動顔検出・ぼかしは誤検出があるため、公開制限や撮影ルールの代替にしない
- 将来写真を公開する場合は、写真単位の同意、投稿前確認、モデレーション、撤回を設計する

## ログ・外部サービス

- Web、API、プロキシ、監視、クラッシュ解析のすべてで、参加トークンをログ禁止項目にする
- 写真バイト列、画像URL、オブジェクトキー、写真ハッシュ、`checkpointId`の大量列挙を通常ログへ出さない
- IPアドレス、User-Agent、Cookieを保存するサービスを洗い出し、目的、保持期間、提供者を承認資料へ記載する。この洗い出し対象に、Cloudflare Worker・アクセスログの保存地域と、Cloud Runリクエストログの保存地域の確認を含める（#22レビュー指摘、2026-10-26）
- 行動解析、広告Cookie、セッション録画ツールは原則使用しない
- 本番DBとバックアップへのアクセスを技術責任者に限定し、アクセス手順を記録する

## インシデント対応

写真メタデータ・経路の漏えい、旧クラウド写真の誤表示/期限超過、端末画像の誤送信が疑われる場合は新規受付を停止し、技術責任者・個人情報責任者（Mino829）へ連絡する。端末内画像をサーバーから回収・消去できないため、参加者への案内も含め大学の規程に従って再開条件を判断する。

## 未決事項

- 保存期間の大学承認。開発側既定（`MemorySession` TTL 6h、`delete_after`=失効後24h、APIセキュリティログ30日、DBバックアップ最大7日）は提案値であって確定値ではない
- 新方式の同意文の正本（Backend配信 vs /log同梱）、新しい版、日本語・英語の最終版と大学承認。旧`2026-memory-photo-no-gps-draft-1`を新方式に流用しない
- 大学への申請・確認手続き
- 未成年参加者がいる場合の扱い
- 研究データとして二次利用する可能性の有無
- データ管理責任者、問い合わせ先、インシデント連絡先（個人情報責任者はMino829に確定済み）
- サーバー、監視、バックアップの提供者と保存地域。Cloudflare Worker・アクセスログとCloud Runリクエストログの保存地域の確認を含む（#22レビュー指摘）
- 旧サーバー写真の保持・削除保証、既発行URLとバックアップを含む残存確認。新規写真用のCloud Storageは採用しない
- 将来の写真公開・友人共有を行うか。MVPでは行わない
